# 学习计划 设计

日期：2026-11-26　状态：待用户确认

## 意图与原因

用户想在首页「日常工具」里增加「学习计划」，**自己按日期定制学习安排，打开就能明确知道今天要学什么**。
用户的工作方式：先定一个半年或一年的大计划（要学哪些方向），再拆到各个月细化；每一项学习内容自己写上起止日期。

## 目标

- 建立「大计划」，有名称、起止日期（如「2027 上半年」）。
- 在大计划下建「学习项」：名称、起止日期、可选备注（如「Python 基础，12/1–12/10」）。
- 「今天」视图：列出所有日期覆盖所选日期的学习项，显示进度（第几天 / 共几天），可以勾选「今天学完了」；还列出即将开始的项。
- 可以翻到前一天 / 后一天、回到今天，查看或补勾其他日期。
- 「按月看」视图：一个月里每个学习项占哪几天，一眼看清整月安排。
- 每个学习项能看到进度：已完成天数 / 总天数；落下的日子（日期已过、没勾选）能看出来。
- 学习项和大计划可以增删改；改日期不丢已有勾选。

## 非目标 / 反目标

- 不做「只写总量、系统自动摊到每天」（用户选择自己定日期）。
- 落下后不自动重排、不自动顺延，只显示落下了；日期由用户自己改。
- 不接入 AI，不做推送通知，不做连续打卡天数、排行榜等统计（以后可以加，本次不做）。
- 反目标：勾选记录或计划因为改日期、翻页、删除其他项而意外丢失。

## 约束

- 零第三方依赖，沿用现有结构：`server.js` 的路由、`lib/` 放纯逻辑并带离线测试、`public/app.js` 的视图切换、`public/index.html` 的视图骨架。
- 日期一律为 `YYYY-MM-DD` 字符串，按服务器本地时间的「今天」；与每周菜单一致。
- 不需要新增配置；不依赖外部服务。
- 数据库升级方式沿用 `CREATE TABLE IF NOT EXISTS`，旧库启动后自动建表。

## 已考虑的做法

- **A. 三张表（已选）**：`study_plans`、`study_items`、`study_checks`。进度可以直接算，按日期 / 月份查询简单，以后加统计容易。代价是新增表和接口。
- B. 整个计划存成一份 JSON：改动最小，但多设备同时改会覆盖，勾选记录越积越多，服务端无法按日期查询。不选。

## 已定的设计

### 数据

| 表 | 字段 | 说明 |
|---|---|---|
| `study_plans` | `id`、`name`、`start_date`、`end_date`、`sort`、`created_at` | 大计划；起止日期必填，结束不早于开始 |
| `study_items` | `id`、`plan_id`（→ `study_plans`，级联删除）、`name`、`start_date`、`end_date`、`note`、`sort` | 学习项；起止日期必填，结束不早于开始 |
| `study_checks` | `item_id`（→ `study_items`，级联删除）、`date`，`PRIMARY KEY(item_id, date)` | 某项在某天已学完；重复勾选只保留一条 |

索引：`study_items(plan_id)`、`study_items(start_date, end_date)`、`study_checks(date)`。

规则：

- 勾选以「某项在某一天」为单位，只能勾选日期落在该项起止日期之内的那一天。
- 改学习项日期不会删除勾选记录；落在新日期范围之外的旧勾选保留在库里，但不计入进度（日期改回来后又会算上）。
- 学习项的日期**不要求**落在大计划的起止之内（保持灵活，只在界面上提示超出）。
- 删除大计划时，其下学习项和勾选一并删除，前端删除前弹确认并写明会删多少项。
- **不做自动清理**（和每周菜单不同，这是长期记录）。

### 纯逻辑（`lib/study.js`，无 I/O）

- `daysBetween(start, end)`：含首尾的天数。
- `itemsOnDate(items, date)`：覆盖该日期的学习项。
- `upcoming(items, date, limit)`：开始日期晚于该日期的最近几项。
- `progress(item, checkedDates, today)`：返回 `{total, done, dayIndex, missed}`。`done` 只数落在项日期范围内的勾选；`dayIndex` 为所选日期是该项第几天；`missed` 为范围内已过去（早于 today）但没勾选的天数。
- `monthLayout(items, year, month)`：每个项在该月占哪几天（供「按月看」渲染）。

### 接口（均需登录，错误统一 `{error}`）

| 方法 路径 | 说明 |
|---|---|
| `GET /api/study/plans` | 大计划列表，附学习项数量 |
| `POST /api/study/plans` / `PUT /api/study/plans/:id` / `DELETE /api/study/plans/:id` | 新增 / 修改 / 删除（含下级） |
| `GET /api/study/items?plan=` | 学习项列表（可按大计划过滤），附已勾选日期 |
| `POST /api/study/items` / `PUT /api/study/items/:id` / `DELETE /api/study/items/:id` | 新增 / 修改 / 删除 |
| `GET /api/study/day?date=` | 某天要学的：`{date, items:[{…学习项, checked, dayIndex, total, done}], upcoming:[…]}` |
| `GET /api/study/month?month=YYYY-MM` | 某月每个学习项占的天数及勾选情况 |
| `PUT /api/study/check` `{item_id, date, checked}` | 勾选 / 取消勾选；日期不在该项范围内返回 400 |

### 界面

- 工具页 `#view-tools` 增加第二张卡片「学习计划」，进入新视图 `#view-study`；不占底部标签。
- 视图内三个切换：**今天**（默认）、**按月看**、**大计划**。
- 今天：顶部日期导航（前一天 / 后一天 / 回到今天）；每个学习项一行，左侧勾选框，显示名称、「第 3 天 / 共 10 天」、备注、已落下天数的提示；下方「即将开始」。
- 按月看：月份导航；每个学习项一行，用色块标出占的天数，已勾选的色块变实。
- 大计划：大计划卡片，点开看其学习项并增删改；日期用日期选择控件，保存时检查结束不早于开始。
- 删除一律弹确认。样式沿用现有的 `tool-card`、`menu-nav` 等。

### 测试

- `test/smoke.js` 增加学习计划接口的冒烟检查（增删改、勾选、范围外勾选被拒绝、级联删除、`day` / `month` 返回）。

## 我替用户做的决定（请核对）

1. 学习项日期可以超出大计划的起止（只提示，不禁止）。
2. 落下的日子只显示，不自动重排、不自动顺延。
3. 「即将开始」显示最近 3 项。
4. 勾选只允许落在项日期范围内的日期。
5. 不做自动清理，不做连续打卡统计。
