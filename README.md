# 家庭物资清点表

记录家里的物资、数量和存放位置，电脑和手机都能查看、修改。零第三方依赖，只需要 Node.js（≥ 22.5，自带 SQLite）。

**一句话说清它能做什么**：家里有什么、放在哪、还剩多少、什么时候过期、该买什么、这周吃什么，都记在一个自己部署的小网页里；买东西时可以**说一句话、拍一张小票或说一段话**就入库。

## 快速开始

Windows 上双击 `start.bat`（或在本目录执行 `node server.js`），启动后终端会打印访问地址：

```
  本机：   http://localhost:3000
  手机访问：http://192.168.1.150:3000  （需与本机在同一 WiFi）
```

- 初始密码：`home1234`（首次启动时也可用环境变量 `INVENTORY_PASSWORD` 指定），**登录后请立刻在「设置」里修改**。
- 端口可用环境变量 `PORT` 修改。
- 手机浏览器打开后选择「添加到主屏幕」，即可像 App 一样全屏使用。
- 手机连不上：检查 Windows 防火墙是否放行了 `node.exe` 的入站连接（首次启动通常会弹窗询问，选择「允许」）。
- 开机自启（Windows，可选）：`Win + R` 输入 `shell:startup`，把 `start.bat` 的快捷方式放进去。

在 Linux 开发板、NAS 或云服务器上长期运行，见 [配置步骤](docs/配置步骤.md)。

## 功能说明

底部有 6 个标签：**首页、物品、清单、图纸、位置、设置**。每周菜单、学习计划、每周工作和以后的小工具放在首页的「日常工具」卡片里，不占底部标签。

### 首页仪表盘

打开就看到四个数字：物品总数、已过期、30 天内到期、待购买；下面是四个列表：快到期、库存不足、最近添加、最近变动。点任意一行直接打开该物品，点数字可以直接跳到对应的筛选结果。

### 物品管理

- 每件物品记录：名称、数量 + 单位、分类、存放位置、到期日、备注、图片、最低库存。
- 列表上可以直接点 ＋ / － 改数量。
- **搜索筛选**：关键字（名称 / 备注 / 分类 / 位置）、位置、分类、到期范围。
- **过期提醒**：顶部统计显示已过期 / 30 天内到期的数量，点击即可筛选；列表里用红 / 橙标签高亮。
- **图片**：手机上可以直接拍照，上传前在浏览器内压缩。

### 位置层级

房间 → 柜子 → 层 / 抽屉，层级不限。按上级位置筛选时自动包含下级。首次启动会预置客厅、厨房、卧室、卫生间、阳台、玄关和常见的柜子。

### 户型图纸

上传家里的平面图（可多张，如一楼 / 二楼），把柜子、抽屉等位置「标记」在图上。点标记可以看到那里有多少件物品，并跳转查看或添加；标记可以拖动微调，图纸支持放大缩小。

### 购物清单

- 给物品设「最低库存」，数量低于它就自动出现在清单里（按分类分组）；点「已买」把数量补到最低库存。
- 也可以手动添加条目、勾选、一键清除已买。
- 每周菜单生成的采购项也会作为手动条目加进来（见下）。

### 删除可撤销与回收站

删除物品后弹出的提示上有「撤销」。回收站（设置页）保留 30 天，可以恢复或彻底删除。**数量减到 0（用完）会自动移入回收站**，同样可以撤销。

### 变动记录

每次新增、数量增减、移动位置、修改、删除都有记录，并标注来源：手动 / 一句话 / 小票 / 导入 / 购物清单。物品编辑页底部显示该物品最近 8 条。

### 一句话录入

物品页顶部的输入框。手机上点键盘上的 🎤 就可以说话，例如：

- 「买了两盒酸奶放冷藏，保质期到12月1日」
- 「把电钻放到车库的工具架上」
- 「创可贴用完了」
- 「电池还剩8节」

纯规则解析，**不联网、不需要 AI**，自动识别动作、数量单位、位置（可自动新建层级）、分类、到期日。**永远先弹出确认卡，可以改完再保存。**

**一次说多件事**：

- 用句号、分号或换行隔开：「买了牛奶。买了鸡蛋」，一次最多处理 5 句，超过会提示。
- 说完物品后停顿一下再说保质期，日期会补到前面那件物品上。
- 一串物品不加任何分隔也能拆开：「买了牛肉猪肉猪肉丝排骨」会拆成 4 项；「买了两斤牛肉三斤排骨」会拆成牛肉 2 斤、排骨 3 斤。依据是内置词表（`lib/vocab.js`，可自行增删）和你库存里已有的名字。
- 词表里没有的词不会被拆，整串保持一项，在确认卡上手动改即可。两个词表里的词写在一起但其实是一个产品时（如某口味的饺子）也可能被拆开，遇到就在确认卡上改，或把完整名字加进 `lib/vocab.js` 末尾的 `COMPOUND`。

### 小票录入（可选）

物品页的相机按钮：拍一张购物小票，或选一张 App 订单截图，交给你自己配置的多模态识别服务读出商品，弹出和一句话录入同样的确认卡。

- 库存里已有的物品显示「补货」，没有的显示「新增」；名称里的规格（如 500g）会去掉。
- 小票上的单位和库存单位不同、或小票上的名字和库存名只是相近时，那一条会有警告，请核对。
- 小票上没有位置和到期日，需要你在确认卡上选。
- 同一张小票再识别一次，会提示「好像已经录入过了」。
- 图片只发给你配置的识别服务，**不会保存**；永远先确认再写库存。每天有次数上限（默认 30 次）。

### 语音录入（可选）

物品页的麦克风按钮：点一下开始说话，再点一下结束（最长 30 秒自动结束）。录音交给你自己配置的语音识别服务转成文字，自动填进一句话录入框并解析，弹出确认卡。

- 可以一口气说几件事。识别时提示词会要求模型把不同物品之间加「、」、不同的事之间加句号（模型一般会照做），再交给上面的一句话解析器；没加分隔时，解析器也会按词表尝试拆开。
- **页面必须是 HTTPS**，浏览器才允许录音；没配置语音识别或不是 HTTPS，就看不到麦克风按钮。
- 录音只发给识别服务，**不会保存**；永远先确认再写库存。每天有次数上限（默认 100 次）。

### 每周菜单

入口：首页「日常工具」卡片 → 工具页 → 每周菜单。

- **日历式横排**：周一到周日 7 列、早 / 午 / 晚 3 行，手机上一屏看完整周；每天一种颜色，今天高亮。
- 点任意一格，编辑这一餐的菜：每道菜可以带若干食材，食材的数量可以不填；输入曾经用过的菜名，会自动带出上次写的食材。
- 可以翻到上一周 / 下一周查看或补录，随时「回到本周」；超过约 3 个月的菜单会自动删除。
- **按本周菜单生成采购**：对照库存，缺什么列在确认卡里（一道菜出现一次算 1 份；没写数量且库存里有的食材视为够用），确认后作为手动条目加入购物清单。
- 菜单本身**从不扣库存**；在清单里点「已买」只是勾选，不会自动改库存。

### 学习计划

入口：首页「日常工具」卡片 → 工具页 → 学习计划。自己定日期，打开就知道每天要学什么。

- **两层结构**：先建「大计划」（如「2027 上半年」，有起止日期），再在里面加「学习项」（如「Python 基础，12/1–12/10」，有起止日期和备注）。月计划不单独建，按月份看时自动把落在这个月的学习项排开。
- **两个人各用各的**：页面顶部有两位成员（默认叫「我」和「TA」，点「改名」改成你们自己的名字）。每个大计划属于其中一位，新建时选「谁的计划」；切换成员后，「今天」「按月看」「大计划」都只显示这个人的。选择记在每台手机 / 浏览器上，下次打开还是上次选的人。大计划也可以改成另一位的（学习项和勾选跟着走）。这只是分开显示，**不是权限隔离**：用的是同一个密码，谁都能切换去看、去改对方的计划。升级前已有的计划自动归第一位。
- **今天**：列出所有日期覆盖这一天的学习项，显示「第 3 天 / 共 10 天」、已学天数、备注；点左边的圆圈勾选「今天学完了」。下面还有「即将开始」的最近 3 项。可以翻到前一天 / 后一天，补勾过去的日子，「今天」按钮一键回来。
- **按月看**：一个月里每个学习项占哪几天，已勾选的天实心显示，今天有描边。
- **大计划**：新建、编辑、删除大计划和学习项。学习项的日期可以超出大计划范围（会提示「超出计划范围」）。
- **落下了怎么办**：过去没勾的日子会显示「已落下 X 天」，只提醒，**不会自动重排或顺延**，需要调整就自己改学习项的日期；改日期不会丢已有的勾选。
- 勾选只能落在学习项自己的日期范围内；删除大计划会同时删除其下的学习项和勾选（删除前有确认）。
- 学习计划是长期记录，**不会自动清理**。

### 每周工作

入口：首页「日常工具」卡片 → 工具页 → 每周工作。平时随手记，周末写周报时就知道这周干了什么。页面分两个标签：**记录**（每天做了什么）和**待办**（单独的清单）。

**记录标签**

- **按周显示**：周一到周日每天一组，可以翻上一周 / 下一周，「本周」一键回来。
- **每一天直接添加**：每一天的标题右边有「＋」，点开就在这一天的下面出现一个输入行，回车就记到**这一天**，记完保持展开，方便连续记；再点一下收起。
- **每一条直接删除**：每条记录右边有「×」，一点就删，弹出「已删除」和「撤销」（撤销后会排在当天的最后）。点记录文字可以改文字和日期，或删除。
- **顶部输入框**：随手记到「记到：XX 月 XX 日」那一天（所浏览的周含今天时默认今天，否则默认周一；点某一天的标题可以改记到哪天）。只记「已做」。
- **说话也行**：如果配置了语音识别（需要 HTTPS，见「语音录入」），输入框旁有麦克风，说一段话会按句号 / 分号拆成最多 5 条，直接记入，并弹出「已记录 N 条」和「撤销」。识别错了可以撤销，也可以事后点那条记录修改。语音只记「已做」。

**待办标签**

- **添加**：文字必填，日期**可以不选**（默认不选）。
- **三个视图**：「还没做」（默认）、「已完成」、「全部」。还没做的里面，有日期的按日期从早到晚排，没日期的排在后面；已经过了日期还没做的会标橙色「已过期」。「已完成」最多显示最近 200 条。
- **勾选**：前面的圆圈点一下就算完成，会记下完成日期；再点一下取消。
- **挪到下周**：有日期、没做完的待办有这个按钮，把日期改到「原日期和今天中较晚的那天」所在周的下一周周一。
- **编辑与删除**：点待办文字可以改文字、日期（有「清除日期」），或删除；每行右边的「×」一点即删，同样带「撤销」，撤销会连日期和完成状态一起恢复。
- 待办没有语音录入。

**生成周报**（在记录标签里）：点「生成周报」，得到一段可以直接编辑、一键复制的文字，纯规则拼出来，不用 AI：

  ```
  本周工作（11/23 – 11/29）
  周一
  - 对接 A 项目接口
  周二
  - 修了登录 bug
  - 开周会
  - 写方案
  下周计划
  - 整理测试报告
  - 联系供应商
  ```

- 「做了什么」= 这一周的记录 + 这一周**完成**的待办（按完成那天列，同一天先列记录再列待办）；取消勾选后它会从周报里消失。
- 「下周计划」= **全部没做完的待办**，包括没选日期的和已经过期的；有日期的按日期在前，没日期的在后。
- 这一周没有任何「做了什么」时不生成周报，即使有没做完的待办。

**人员**：现在只有一个人员「我」，页面上看起来就是单人使用。点右上角「人员」可以添加人员（最多 10 个）或改名；有两个人以上，页面顶部才出现切换，每人只看自己的记录和待办，选择记在每台手机 / 浏览器上。这只是分开显示，**不是权限隔离**：用的是同一个密码，谁都能切换去看、去改别人的。不提供删除人员。

**升级**：以前记在每天里的待办，升级后启动时会自动搬进「待办」标签：原来的日期变成待办日期，已完成的完成日期取原来的日期，不用手动操作。

### 正式周报导出（AI 整理 + 套用公司 Word 模板）

入口：每周工作 → 记录标签 → 「整理成正式周报」（在「生成周报」下面）。把本周的记录和待办交给 AI 整理成「项目 + 细节 + 完成度 + 需协调的问题 + 下周计划」，你改一改，再导出成**套用你们公司模板的 `.docx`**。

**一次性准备（设置页的「周报导出」）**

1. **上传周报模板**：公司的周报，必须是 `.docx`（老式 `.doc` 先在 Word 里「另存为」`.docx`）。模板要是「一张表」的结构，并且包含：抬头里的「时间」、「工作内容」「解决方案及结果」表头、「本周工作需协调解决的问题或者建议」、「工作计划」「日期」表头、「部门经理批阅」以及它下面带「日期：2026.11.28」字样的签名行。结构对不上时上传会被拒绝，并说明缺了什么。
2. **上传示例周报**（可选，最多保留 4 份）：以前写过的周报 `.docx`，AI 会参照它们的写法。你导出的周报也会自动成为之后的示例。
3. **基准单休周**：见下面的大小周规则，默认 2026-11-23 那周是单休。

AI 默认**沿用「拍小票」那套配置**（地址、key、模型都不用再填）。想换一个文字模型，或者用完全单独的服务，见 [配置步骤](docs/配置步骤.md) 的「配置周报整理」。

**每周的用法**

1. 在记录页点「整理成正式周报」。
2. 先看到**将发送给 AI 的完整内容**（本周记录、完成的待办、没做完的待办、示例周报），确认后点「发送」。
3. AI 返回草稿，项目、细节、完成度、需协调的问题、下周计划都可以改、可以增删。AI 被要求只使用你记录里的事实，但**不保证准确，请自己核对**，完成度是它估的，尤其要看。
4. 点「导出 docx」，得到套用你模板的文件，文件名形如 `徐晨凯11.23-11.28-周报.docx`（姓名取自模板抬头）。

**大小周的日期规则**（日期由程序算，不是 AI 写的）

| 生成当天 | 本周 | 文件名里的范围 | 「工作计划」的日期 |
|---|---|---|---|
| 周六 | 单休（周六上班） | 周一到周六 | 下周一到下周五 |
| 周五 | 双休 | 周一到周五 | 下周一到下周六 |

其他日子（比如周日补生成、周一）按单双周交替往后推：以设置里的基准单休周为单休，隔一周交替。遇到节假日调休，在草稿顶部点「本周单休 / 本周双休」切换，计划日期和文件名跟着变。「时间」和签名处的日期默认是生成当天，可以改。日期写成 `2026.12.4` 这种不补零的样子，和模板一致。

**导出的文件和你的模板有什么不同**：它就是你的模板，只替换了内容，字体、边框、页边距都不变。唯一的改动是填过的行从「固定行高」改成「最小行高」（否则内容多了 Word 会把多出的部分截掉）。签名栏的姓名原样保留，只换日期。每个项目细节前的编号都从 1 开始。

**隐私**：模板和示例只保存在你自己的服务器上（`data/report/`），不会进 git。整理时，示例和本周记录会发给上面配置的 AI 服务；每次发送前都会先让你预览。每天最多整理 20 次（可在配置里调），用量单独计算，不占用拍小票的次数。

每周工作是长期记录，**不会自动清理**。

### 导入导出

- 导出 CSV（Excel 可直接打开）。
- 导入 CSV 只需要「名称」列，其余可选；位置写成 `厨房 / 吊柜` 会自动创建；自动识别 UTF-8 / GBK 编码；可以带「最低库存」列。

### 密码保护

单一家庭密码，登录状态保留 180 天；改密码后所有设备都需要重新登录。

## 三种快捷录入怎么选

| 方式 | 适合 | 需要联网 / 配置 | 说明 |
|---|---|---|---|
| 一句话（打字，或手机键盘上的 🎤） | 日常随手记 | 都不需要 | 纯规则解析，最快，永远可用 |
| 相机（拍小票 / 订单截图） | 买了一大堆东西 | 需配置识别服务 | 一次录入整张小票 |
| 页面里的麦克风 | 手上不方便打字、想一口气说几件事 | 需 HTTPS + 配置语音识别 | 识别后走和一句话同一套解析 |

三种方式最终都弹出同一张确认卡，核对无误才会写库存。

## 数据与备份

所有数据都在 `data/` 目录：

| 文件 | 内容 |
|---|---|
| `data/inventory.db` | SQLite 数据库（物品、位置、图纸、变动记录、购物清单、菜单） |
| `data/uploads/` | 物品图片和户型图纸 |
| `data/config.json` | 密码哈希、会话密钥，以及（可选）小票识别和语音识别的配置 |
| `data/receipt-usage.json`、`data/asr-usage.json` | 两个识别服务每天的调用次数 |

备份时**整个复制 `data/` 目录**即可；也可以在「设置」里导出 CSV。可用环境变量 `INVENTORY_DATA` 把数据目录放到别处（例如 NAS 的共享盘）。`data/config.json` 里有密钥，备份文件请妥善保管。

## 可选功能的前提条件

| 功能 | 前提 |
|---|---|
| 小票录入 | 服务器上配置一个能读图的识别服务（地址、key、模型） |

没配置的可选功能，对应的按钮不会出现，其余功能不受影响。具体配置见 [配置步骤](docs/配置步骤.md)。

## 测试

```bash
npm test
```

依次运行解析器、词表、菜单、识别服务、WAV 编码器等纯逻辑测试，最后是接口冒烟测试。**冒烟测试需要先启动服务**（默认连 `http://localhost:3000`，可用环境变量 `BASE` 指到别处），并且假定服务启动时没有配置小票识别和语音识别。建议用临时数据目录和另一个端口启动一个测试实例，不要连正式数据：

```bash
INVENTORY_DATA=/tmp/inv-test PORT=3100 node --no-warnings server.js
BASE=http://localhost:3100 node test/smoke.js
```

（上面是 Linux / macOS 的写法；Windows PowerShell 用 `$env:INVENTORY_DATA="D:\inv-test"; $env:PORT=3100; node --no-warnings server.js`，再另开一个窗口 `$env:BASE="http://localhost:3100"; node test/smoke.js`。）

单独运行某项：`node test/parse.test.js`。各测试文件的作用见 [结构框架](docs/结构框架.md)。

## 常见问题

**忘了密码怎么办？** 停掉服务，删除 `data/config.json`，重新启动，会用 `INVENTORY_PASSWORD`（没设就是 `home1234`）重新生成。注意这样会同时清掉 `config.json` 里的小票识别和语音识别配置，需要重新填。

**手机连不上？** 确认手机和电脑在同一 WiFi（访客 WiFi 常常互相隔离）；Windows 防火墙放行 `node.exe`；云服务器检查安全组和防火墙是否放行了端口。

**为什么看不到相机 / 麦克风按钮？** 没有在服务器上配置对应的识别服务；麦克风还需要页面是 HTTPS。

**识别出来的物品不对？** 所有识别结果都先进确认卡，可以直接改；一句话录入里被拆坏的名称，可以把完整名字加进 `lib/vocab.js` 末尾的 `COMPOUND`。

**数据会丢吗？** 都在 `data/` 目录里，定期复制备份即可；删除的物品有 30 天回收站。
