# 正式周报导出（AI 整理 + 套用公司 Word 模板）设计

日期：2026-11-28　状态：待用户确认

## 意图与原因

用户每周要交一份公司的 Word 周报（固定模板，表格式）。平时在「每周工作」里随手记录，但周末仍要手工把零散记录整理成「项目标题 + 若干条细节 + 完成度」的写法，再填进模板。用户希望：**点一下，让 AI 参考以往周报的写法把本周记录整理好，预览改一改，导出一份可以直接交的 docx。** 用户已同意把工作内容发给外部模型，并同意直接用「图片识别」那套 AI 服务和 key。

## 目标

- 在「每周工作」页新增「整理成正式周报」：把本周的记录、本周完成的待办、未完成的待办，加上以往周报作示例，交给 AI，得到一份结构化草稿。
- 草稿可以在页面上**逐项修改**（项目、细节、完成度、需协调的问题、下周计划、日期），满意后**导出 docx**。导出的 docx 就是用户的模板，只替换内容，字体、边框、页边距原样保留。
- **大小周日期规则**：由程序计算，不由 AI 写。周六生成 = 本周单休（周一到周六上班），下周双休，下周计划日期为下周一到下周五；周五生成 = 本周双休，下周单休，下周计划日期为下周一到下周六。
- 模板和示例周报由用户在页面上传，只保存在服务器 `data/` 下；每次发给 AI 之前，先让用户看到将发送的完整内容。
- 导出的周报自动成为之后的示例。

## 非目标 / 反目标

- 不处理老式 `.doc`（只收真正的 `.docx`；用户用 Word「另存为」转换一次）。不做模板设计器，不支持多套模板，不支持每个人员各自的模板（模板里的姓名保持原样）。
- 不做定时自动生成，不修改历史周报，不改现有的纯文字周报（「生成周报」按钮保持不变）。
- 不让 AI 决定日期，不让 AI 直接写进文件：AI 只返回结构化草稿，用户确认后才导出。
- 反目标：AI 编造记录里没有的事情而用户没发现；日期写错（尤其大小周）；导出的文件 Word 打不开或提示修复；密钥、模板、示例内容进入日志、git 或接口响应；一次发给 AI 的内容用户没看到过。

## 约束

- 零第三方依赖：docx 是 zip + XML，读写 zip 用 Node 自带的 `zlib` 自己写（CRC32 自己实现，不依赖较新的 Node 版本）。
- 沿用现有结构：`lib/` 放纯逻辑并带离线测试，`server.js` 加路由，`public/` 加界面；错误用 `HttpError` 和中文提示；AI 调用复用 `lib/provider-guard.js` 的 `callProvider` / `createUsage` 和 `lib/receipt.js` 的 `extractReplyText`。
- 模板、示例、用量、设置全部放 `data/report/`（`data/` 已在 `.gitignore`）；**测试和仓库里不得出现用户的真实周报内容**，测试用的 docx 由测试代码现场构造。
- 不启动测试服务器或浏览器；冒烟测试只写不跑；前端靠 `node --check`。**无法在真实的 Word 里验证导出的文件，这是已知风险**，由用户验收，并靠测试里对输出 zip / XML 的结构校验降低风险。
- 上传大小：模板和示例 docx 各 ≤ 5 MB；解压后总大小 ≤ 30 MB，条目数 ≤ 200（防压缩炸弹）。

## 已考虑的做法

- **A. 在用户的模板上复制行、填内容（已选）**：保留全部原样式；代价是要解析模板结构、处理行高和编号。
- B. 程序从零生成一份相似的 docx：不依赖模板结构，但字体、边框、间距一定有细微差别。不选。
- AI 部分：让 AI 直接输出整份 docx 的内容不可控；让它输出受限制的 JSON、由程序校验后填表（已选）。

## 已定的设计

### 模板（用户提供的真实结构）

整份周报是一张表（6 列网格，大量合并单元格），按**关键字识别行**，不写死行号：

| 区域 | 识别方式 | 填法 |
|---|---|---|
| 抬头行 | 含「部门」「姓名」「时间」的单元格 | 只改「时间」右边那格为生成日期（`YYYY.M.D`，不补零） |
| 工作项行 | 表头行含「工作内容」「解决方案及结果」，到「本周工作需协调解决的问题或者建议」之前 | 取第一条工作项行当样板，复制 N 份。每行**恰好 3 个单元格**（按 `<w:tc>` 顺序）：①序号（占 1 列）；②内容（跨 3 列）：第一段是项目标题（无编号），其后是若干带自动编号的细节段；③完成度（跨 2 列）：**表头虽然写「解决方案及结果」，实际填的是百分数，格式 `N%`，如 `100%`** |
| 需协调的问题 | 紧跟「本周工作需协调解决的问题或者建议」的下一行 | 替换文字，默认「无」 |
| 计划行 | 表头行含「工作计划」「日期」，到「部门经理批阅」之前 | 取第一条计划行当样板，复制 N 份。每行**恰好 3 个单元格**：①序号（占 1 列）；②计划文字（跨 3 列）；③日期（跨 2 列，每行相同，如 `2026.11.30-2026.12.4`） |
| 签名行 | 「部门经理批阅」的下一行 | **只替换其中形如 `日期： 2026.11.28` 的日期**，签名姓名等其余文字原样保留 |

- **样板行与原有内容**：工作项区和计划区各以**第一行**为样板，区内其余行（模板里上周留下的内容）全部丢弃，由新内容替换。序号一律重排为 `1..N`。样板的内容格必须有「一个标题段 + 至少一个带编号的细节段」，两种段落的段落属性、run 属性分别克隆；某个项目没有细节行时只输出标题段。
- **单元格定位**：按行内 `<w:tc>` 的顺序取（工作项行和计划行都必须恰好 3 个），并核对 `gridSpan` 依次为 1 / 3 / 2；对不上就在上传模板时拒绝。抬头行是 6 个单元格「部门｜值｜姓名｜值｜时间｜值」，按标签文字找到后取它右边那一格。
- 缺少任何一个关键字 / 找不到样板行 / 样板不满足上面的条件时，上传模板时就报错：「模板结构不认识：找不到 XXX」，并且上传时用示例数据试填一次，试填失败也拒绝。
- **文字格式（已对照真实模板核对）**：每个单元格里一段文字只有一个 run，格式写在段落标记和 run 上；整表为 A4、四边页边距 1 cm、宋体 10.5 号（标题 18 号）。因此直接用样板段落的 XML 做模板、替换其中的 `<w:t>` 文字即可；如果遇到被拆成多个 run 的样板段落，保留第一个 run 的属性、合并文字。
- **行高**：工作项行和计划行是固定行高（`trHeight … hRule="exact"`），内容多了 Word 会截断。填过的行统一改为「最小行高」（`atLeast`），这是对模板**唯一的改动**。
- **自动编号**：每个项目的细节行用各自的一套编号（`numId`）。新增项目时在 `numbering.xml` 里为它新建一个 `<w:num>`，指向原来的 `abstractNum` 并带 `startOverride=1`，保证每个项目都从 1 开始。
- 所有填入的文字做 XML 转义，并去掉控制字符；每个单元格内的格式沿用样板段落的段落属性和 run 属性。
- 输出 zip：保留模板里除 `document.xml`、`numbering.xml` 以外的所有条目原样；`[Content_Types].xml` 排第一；文件名用 UTF-8 并置位标志。输出前用自己的 zip 读取器再解开一遍并检查 XML 标签配对。

### 日期规则（纯逻辑，`lib/report-dates.js`）

- 输入：要生成的那一周的周一 `start`，生成当天 `today`（用**浏览器的本地日期**，不用服务器日期），基准单休周 `anchor`（某个周一，默认 `2026-11-23`）。
- **本周类型 `kind`**：若 `today` 落在 `start` 那一周内：周六 ⇒ `single`，周五 ⇒ `double`；其他情况（或 `today` 不在那一周内）按交替推：`start` 与 `anchor` 相差的整周数为偶数 ⇒ `single`，奇数 ⇒ `double`。用户可在预览里手动改成另一种。
- 本周范围：`single` ⇒ 周一到周六，`double` ⇒ 周一到周五（用于文件名）。下周计划日期：本周 `single` ⇒ 下周一到下周五；本周 `double` ⇒ 下周一到下周六；格式 `YYYY.M.D-YYYY.M.D`，跨年也写年份。
- 文件名：`<模板里的姓名><本周起 M.D>-<本周止 M.D>-周报.docx`，如 `徐晨凯11.23-11.28-周报.docx`；姓名取模板抬头的「姓名」右边那格。
- 「时间」和签名日期默认 = `today`，预览里可改。

### AI 整理

- 配置（`lib/report-ai.js` 的 `resolveConfig`）：`config.report`（`url`、`key`、`model`、`format`、`extra`、`timeoutSec`、`dailyLimit`）及环境变量 `REPORT_*`。**沿用图片识别的规则，防止把 key 发给另一家服务：**
  - 周报**没有配置 `url`** ⇒ `url`、`key`、`format`、`extra` 从图片识别（`config.receipt` / `RECEIPT_*`）沿用，其中任何一项周报自己配了就用自己的；`model` 周报自己配了就用自己的（常见做法：同一家服务换一个文字模型），否则沿用。
  - 周报**配置了 `url`** ⇒ **什么都不沿用**：`key`、`model` 必须周报自己配齐，缺了就是 `problem`「周报配置不完整，缺少：…」；`format` 缺省 `openai`，`extra` 缺省 `{}`。
  - `timeoutSec`（默认 90）和 `dailyLimit`（默认 20）**只看周报自己的配置，从不沿用图片识别的值**；用量单独记在 `data/report/usage.json`，不占用小票的额度。
  - 错误提示里绝不出现 key。
- 请求：`openai` / `anthropic` / `responses` 三种格式的纯文本版本（回复解析复用 `extractReplyText`）。
- 提示词内容：本周记录（按日期和星期列出）、本周完成的待办（带完成日期）、未完成的待办（带待办日期或「没选日期」）、示例周报（最多 4 份，每份 ≤ 6000 字）；要求只返回 JSON：`{"items":[{"title":"项目名","lines":["细节…"],"progress":100}],"issues":"无","plan":["计划…"]}`；规则：按项目归类，标题和细节的写法参照示例；**只使用记录里出现的事实，不得编造**；完成度是 0–100 的整数；计划来自未完成待办和记录里能看出的后续工作；不写日期。
- 回复校验（`parseDraft`）：容错取出 JSON；`items` ≤ 12 项，每项 `title` ≤ 60 字、`lines` ≤ 10 条且每条 ≤ 200 字、`progress` 取整并限制在 0–100；`issues` ≤ 200 字；`plan` ≤ 12 条且每条 ≤ 200 字；缺字段按默认值补（`issues` 缺省「无」），完全不是 JSON 或 `items` 为空 ⇒ 502「AI 返回了无法理解的内容，请重试」。
- 这一周没有任何记录、也没有完成的待办时不调用 AI，提示「这一周还没有记录」（与纯文字周报一致）。
- 示例来源：`data/report/examples/` 下的纯文字（用户上传 docx 时抽取文字存下，**不保留原文件**），最多 4 份，新的顶掉最旧的；导出成功后，把导出内容的文字存为新示例，周范围相同的覆盖旧的。

### 接口（均需登录，错误统一 `{error}`）

| 方法 路径 | 说明 |
|---|---|
| `GET /api/report/status` | `{enabled, hasTemplate, examples:[{id, title, chars}], anchor, problem?}`；`enabled` = AI 已配置（含沿用图片识别的配置）；不返回任何 key |
| `PUT /api/report/settings` `{anchor}` | 基准单休周；必须是真实日期，自动归到当周周一 |
| `POST /api/report/template` | 请求体是 docx 二进制（≤ 5 MB）；校验结构并试填，成功后替换模板 |
| `POST /api/report/examples` | 请求体是 docx 二进制；抽取文字存为示例（≤ 6000 字，超出截断并提示） |
| `DELETE /api/report/examples/:id` | 删除一份示例 |
| `GET /api/report/dates?start=&today=&kind=` | 返回按规则算出的 `{kind, from, to, time, planRange, filename}`；`kind` 可选，给了就用它（`single`/`double`） |
| `POST /api/report/prepare` `{person, start}` | 组装发给 AI 的完整提示词，**不调用 AI** → `{prompt, hash, chars, examples, empty}`；`hash` 是提示词的 SHA-256（十六进制前 32 位），用于发送前预览 |
| `POST /api/report/generate` `{person, start, hash}` | 服务端**重新组装**提示词并计算指纹，与 `hash` 不一致（预览之后记录、待办或示例变了）⇒ 409「内容在预览之后有变化，请重新预览」，**不调用 AI**；一致才调 AI → 草稿 `{items, issues, plan}`。其他错误码：503 未配置 / 409 还没上传模板 / 429 次数用完或正在整理上一份 / 502 AI 出错 / 504 超时；整理期间同一时间只处理一个 |
| `POST /api/report/export` `{draft, time, planRange, kind, start}` | 校验后返回 docx 二进制，`Content-Disposition` 带中文文件名（RFC 5987）；同时把内容存为示例。校验：`draft.items` **至少 1 项**，每项 `title` 非空（去空白后）、`lines` 可以为空数组（只输出标题）、`progress` 为 0–100 的整数；`draft.plan` 可以为空数组（此时计划区保留**一行全空**的样板，序号也留空），非空的每条文字非空；`draft.issues` 为空时按「无」处理；`time` 与 `planRange` 必须是 `YYYY.M.D` / `YYYY.M.D-YYYY.M.D` 格式；各项数量和长度上限同上。「时间」和签名处的日期是**同一个值**（`time`） |

- `person` 校验沿用 `workPersonId`；`start` 归一到周一；缺少模板时 `prepare` / `generate` / `export` 返回 409「请先在设置里上传周报模板」。
- 服务启动时只在日志里打印「周报整理已启用（沿用图片识别的配置 / 单独配置）」之类，**不打印模型名以外的任何配置**。

### 界面

- **设置页**新增「周报导出」一节：状态（AI 是否可用、是否有模板、示例几份）、上传模板、上传示例（可多选，逐份上传）、示例列表（可删）、基准单休周日期。说明文字明确：「模板和示例只保存在你的服务器上；整理周报时，示例和本周记录会发给图片识别用的那个 AI 服务。」
- **每周工作页（记录标签）**：在「生成周报」旁增加「整理成正式周报」，AI 不可用或没有模板时按钮置灰并提示去设置里配置。
  1. 点击 → 弹层 A 显示「将发送给 AI 的内容」（`prepare` 返回的完整文字，只读，可滚动）和字数、示例份数，按钮「发送」/「取消」。
  2. 发送（带上 `prepare` 返回的 `hash`；若返回 409「内容在预览之后有变化」就回到第 1 步重新预览）→ 显示「整理中…」→ 弹层 B 草稿：本周类型（单休 / 双休，可切换，切换后日期和文件名重新计算）、「时间」（同时是签名处的日期）、每个项目（标题、细节每行一条、完成度）可增删改、「需协调的问题」、「下周计划」每条可增删改、计划日期（可改）、文件名。至少保留一个项目。
  3. 「导出 docx」→ 下载。「重新整理」回到第 2 步。
- 草稿弹层里所有字段用 `value` 赋值，不经 `innerHTML`；打开期间禁止重复提交，导出失败错误显示在弹层里。

## 我替用户做的决定（请核对）

1. 只收 `.docx`；用户用 Word 把 `.doc` 另存为 `.docx`。
2. 示例只存纯文字、最多 4 份、新的顶掉旧的；导出的周报自动成为示例。
3. 完成度由 AI 估，预览里可改；AI 不写日期，日期由程序按大小周规则算。
4. 每次发送给 AI 前都显示完整内容，没有「不再提示」选项。
5. AI 配置默认沿用图片识别的；周报单独限额（默认每天 20 次）和用量文件。
6. 填过的行把固定行高改成最小行高；这是对模板唯一的改动。
7. 签名栏的姓名原样保留，只换日期；「时间」和签名处的日期是同一个值，默认生成当天（浏览器日期），预览里可改。
8. 基准单休周默认 2026-11-23，可在设置里改；周五 / 周六生成时以当天为准，其余日子按交替推，预览里可手动切换。
9. 一份周报最多 12 个项目、每项最多 10 条细节、计划最多 12 条。
10. 模板里的姓名不随「人员」切换而变（不做每人一套模板）。
11. 模板的单元格对应关系按用户的真实文件写死在文档里（工作项行 / 计划行各 3 个单元格；完成度写成 `N%`）；除第一行样板外，模板里原有的内容都会被丢弃。
12. 发送给 AI 的内容靠「预览时的指纹」保证与实际发送一致，不一致就拒绝并要求重新预览。
13. 周报单独配了地址时，不沿用图片识别的 key；超时和每日限额只看周报自己的配置。
14. 导出时至少要有 1 个工作项；计划可以为空（保留一行全空的计划行）。
