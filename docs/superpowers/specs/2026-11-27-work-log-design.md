# 每周工作记录（每周工作了什么）设计

日期：2026-11-27　状态：待用户确认

## 意图与原因

用户老是记不起每周干了什么，周末写周报时无从下手。希望：**平时随手打字或说一句话，就记到当天；周末打开就能看到这一周做了什么；也能顺手记下周的待办。** 入口放在「日常工具」里，与每周菜单、学习计划并列。

用户已定的取向：现在只记他自己的，但**数据里要留好人员，以后可以添加人员**（例如老婆也想记）。

## 目标

- 工具页新增卡片「每周工作」，进入新视图。
- **按周显示**：周一到周日，每天一组记录；可翻上一周 / 下一周，一键回到本周（沿用每周菜单的操作习惯）。
- **随手记**：顶部一个输入框，输入一句话回车就记到「目标日」；有语音识别时旁边有麦克风按钮，说一句话（或几句）自动记成多条。
- **两种记录**：「已做」和「待办」。输入框旁有开关选这条记什么。
- **待办**可以勾选完成；没做完的待办可以一键挪到下周一。
- **生成周报**：一个按钮，把这一周整理成一段文字（本周做了什么，按天列出；下周计划），可以编辑后一键复制。
- 记录可以修改文字、改日期、改类型、删除。
- **人员**：数据按人员分开。现在只有一个人员「我」，页面上看起来就是单人使用；可以添加人员、给人员改名；有了第二个人员后，页面顶部才出现人员切换，每人只看自己的。

## 非目标 / 反目标

- 不用 AI 总结周报，周报纯规则拼接，不联网（以后想加可以另做）。
- 不做项目分类、标签、工时统计、提醒通知、导出 Word / Excel。
- 不做删除人员（只能加、改名），不做权限隔离：同一个密码，谁都能切到别人的记录。
- 不做自动清理，这是长期记录。
- 反目标：语音识别错了悄悄记进去、事后找不到也改不了；记到了错误的日期而用户没发现；一条记录因为翻页或切换人员而丢失。

## 约束

- 零第三方依赖；沿用现有结构：`lib/` 放纯逻辑并带离线测试，`server.js` 加表和 `/api/work/*`，`public/` 加视图和样式。
- 日期一律 `YYYY-MM-DD`；周一为一周起点；「今天」前端用浏览器本地日期（与每周菜单一致）；周计算复用 `lib/menu.js` 的 `weekStart` / `addDays`。
- 旧库升级靠 `CREATE TABLE IF NOT EXISTS`，不影响已有数据。
- 语音识别依赖已有配置（需 HTTPS + 服务器已配置识别服务）；没有时麦克风按钮不显示，打字照常可用。
- **已有的物品页语音录入行为不能变**（现在的语音状态机绑定在物品页输入框和「录入」流程上，要改成两处都能用，同一时间只能有一处在录音）。
- 不启动测试服务器或浏览器；冒烟测试只写不跑，前端靠 `node --check` 和真机验证。

## 已考虑的做法

关于人员怎么存：

- **A. 工作记录自己建一张人员表（已选）**：初始一个「我」，可添加、改名；与学习计划互不牵连。
- B. 复用学习计划的成员：成员固定两位、只能改名，做不到「添加人员」。不选。
- C. 现在完全不做人员，以后再加列：以后要再开发一次。不选。

## 已定的设计

### 数据

| 表 | 字段 | 说明 |
|---|---|---|
| `work_people` | `id`、`name`、`sort` | 首次启动为空时预置一行「我」；名字去首尾空白后非空、最长 20 字；最多 10 人 |
| `work_entries` | `id`、`person_id`（→ `work_people`，级联删除）、`date`、`kind`（`done` / `todo`）、`text`、`done`（0/1，仅待办有意义）、`created_at` | 一条记录一行文字，`text` 去首尾空白后非空、最长 200 字 |

索引：`work_entries(person_id, date)`。同一天内按 `id` 升序显示（即记录的先后）。

### 规则

- 「目标日」：输入框把新记录记到哪一天。浏览的周包含今天时默认今天，否则默认该周周一；点某一天的标题可改目标日；界面上要明确显示「记到：11月27日 周五」。
- 待办勾选完成后保持待办身份，**在周报里算作「本周做了什么」**（按它自己的日期）。
- 「挪到下周」：把待办的日期改为**它所在周的下一周周一**。
- 语音识别出的文字按句号 / 分号 / 换行拆成多条，最多 5 条，每条按当前开关选的类型记入；记完弹出「已记录 N 条」和**「撤销」**（一次撤销整批）。不做「先确认再记」，因为这是随手笔记，错了可以撤销，也可以事后修改。
- **周报内容**（纯文字）：
  - 标题「本周工作（11/23 – 11/29）」。
  - 按周一到周日列出当天的「已做」和「已完成的待办」，每条一行以「- 」开头；没有内容的日子不列。
  - 「下周计划」：本周所有**未完成**的待办 + 日期落在下一周的待办，每条一行；没有则整节省略。
  - 本周什么都没有记时，周报按钮提示「这一周还没有记录」，不生成。
  - 周报显示在弹层的文本框里，可以直接编辑，「复制」按钮写入剪贴板；剪贴板不可用时选中文本让用户手动复制。

### 接口（均需登录，错误统一 `{error}`）

| 方法 路径 | 说明 |
|---|---|
| `GET /api/work/people` | 人员列表 `[{id, name}]` |
| `POST /api/work/people` `{name}` | 添加；空名 400「名称不能为空」，超 20 字 400「名称最长 20 字」，已满 10 人 400「人员最多 10 个」 |
| `PUT /api/work/people/:id` `{name}` | 改名，规则同上；不存在 404「人员不存在」 |
| `GET /api/work/week?start=YYYY-MM-DD&person=<id>` | 一周的记录 → `{start, end, days:[{date, entries:[{id, kind, text, done, date}]}]}`；`start` 自动归一到周一；`person` **必填**且必须存在，否则 400「人员不存在」 |
| `POST /api/work/entries` `{person_id, date, kind, text}` | 新增一条；校验：人员存在、日期有效、`kind` 只能是 `done`/`todo`、文字非空且 ≤ 200 字 |
| `POST /api/work/entries/batch` `{person_id, date, kind, text}` | 一次记多条（语音用）：`text` 是未拆分的口述文字，服务端按句号 / 分号 / 换行拆成最多 5 条，整批在一个事务里；拆不出内容 400「没有可记录的内容」；返回 `{ids:[…], count, truncated}`，`ids` 供撤销，`truncated` 表示超过 5 句、后面的没有记 |
| `PUT /api/work/entries/:id` `{text?, kind?, date?, done?}` | 局部修改，给了的字段才改，校验同上 |
| `DELETE /api/work/entries/:id` | 删除；撤销一批时前端逐条调用或用下一行 |
| `POST /api/work/entries/delete` `{ids:[…]}` | 批量删除（撤销用），最多 20 个 id，不存在的忽略 → `{removed}` |
| `GET /api/work/report?start=&person=` | 生成周报 → `{text, empty}`；`empty` 为 true 表示本周没有记录 |

### 纯逻辑 `lib/work.js`

- `splitSpoken(text, max = 5)`：按 `。！？；;\n` 拆句，去空白、丢空句，返回 `{parts, truncated}`，`parts` 最多 `max` 条，多于 `max` 条时 `truncated` 为真。
- `buildReport({start, entries, nextWeekTodos})`：生成上面规定的周报文字，返回 `{text, empty}`；`entries` 是本周记录，`nextWeekTodos` 是日期落在下一周的待办；日期用 `lib/menu.js` 的周计算。
- `nextMonday(dateStr)`：给定日期，返回其下一周的周一。

### 界面

```
每周工作                           [人员]
（有 2 人以上时这里出现：[我][老婆]）
‹  11月23日 – 11月29日  ›   [本周]
记到：11月27日 周五
[ 今天做了什么…            ] [🎤] [已做|待办] [记]
周一  · 对接 A 项目接口
周二  · 修了登录 bug     · 开周会
周五  ☐ 整理测试报告  [挪到下周]
[生成周报]
```

- 每条记录点一下进入编辑（改文字、日期、类型，或删除）；待办前有勾选框。
- 「人员」按钮始终在标题栏：打开一个弹层，列出所有人员（每人有「改名」）和「＋ 添加人员」。当前选中的人员存在 `localStorage` 的 `work_person`，已不存在时回退到第一位。
- 宽屏沿用其他工具页的居中布局；手机一屏能看完一周的主要内容，不强求。
- **语音**：把现有语音录入改造成「谁点的麦克风就把识别结果交给谁」，物品页交给一句话录入（行为不变），本页交给批量记录；任何时候只有一处在录音，离开页面即放弃录音。

## 我替用户做的决定（请核对）

1. 语音记录**直接记入并给「撤销」**，不先弹确认卡。
2. 已勾选完成的待办在周报里算「本周做了什么」。
3. 「下周计划」= 本周未完成待办 + 已定在下周的待办。
4. 「挪到下周」挪到它所在周的下一周周一。
5. 人员最多 10 个，只能加和改名，不能删。
6. 单条记录最多 200 字，语音一次最多 5 条。
7. 不做 AI 总结周报、不做分类标签。
