# 学习计划：区分是谁的计划 设计（小改动）

日期：2026-11-27　状态：设计已向用户讲解，用户确认「今天页只看自己的」

## 意图与原因

网站由用户和老婆两个人共用（同一个密码、同一份数据）。学习计划现在是一整份，两个人的计划混在一起。用户希望**计划可以选是谁的，两个人各做各的计划**，打开只看到自己的。

## 目标

- 有两位「成员」，名字可以改（默认「我」「TA」）。
- 每个大计划属于一位成员；新建时选，编辑时可改。
- 学习计划页顶部有成员切换；选中谁，「今天」「按月看」「大计划」三个面板就只显示谁的。
- 切换选择记在这台设备上（浏览器本地存储），下次打开还是上次选的人；没有记录时默认第一位。
- 已有的计划全部归到第一位成员名下，旧数据自动升级。

## 非目标 / 反目标

- 不做账号和权限：仍是单一家庭密码，谁都能切换去看对方的计划，也能改（这是夫妻共用的便利，不是隔离）。
- 不做「我们俩」合并视图（用户选择只看自己的）。
- 不做成员的新增和删除，固定两位，只能改名。
- 反目标：旧计划升级后丢失或错归属；切换成员后还显示上一个人的内容；两个人的勾选互相影响（勾选跟着学习项走，学习项属于某个计划，天然隔离）。

## 约束

- 零第三方依赖；沿用现有结构。旧库升级用 `CREATE TABLE IF NOT EXISTS` 和 `ALTER TABLE ADD COLUMN`。
- 日期、校验、错误提示沿用学习计划原设计。

## 已定的设计

### 数据

- 新表 `study_members(id, name, sort)`。首次启动时若为空，插入两行：「我」「TA」。
- `study_plans` 加列 `member_id INTEGER NOT NULL DEFAULT 0`；启动时把 `member_id = 0` 的行更新为第一位成员的 id（`sort` 最小者）。
- 学习项、勾选不变，归属通过所属大计划得到。

### 接口（变化）

| 接口 | 变化 |
|---|---|
| `GET /api/study/members` | 新增，返回 `[{id, name}]`（按 `sort`） |
| `PUT /api/study/members/:id` `{name}` | 新增，改名；去掉首尾空白后不能为空，最长 20 字；不存在 404 |
| `GET /api/study/plans?member=<id>` | 可选过滤；不传则返回全部；返回里每项多 `member_id` |
| `POST /api/study/plans` / `PUT /api/study/plans/:id` | 请求体新增 `member_id`（必填，必须是存在的成员，否则 400「成员不存在」） |
| `GET /api/study/items` | 新增可选 `member` 过滤（与 `plan` 可同时给）；`member` 非正整数 400 |
| `GET /api/study/day?date=&member=` | `member` **必填**且必须存在，否则 400；只返回该成员的学习项和「即将开始」 |
| `GET /api/study/month?month=&member=` | 同上 |
| `PUT /api/study/check` | 不变 |

### 界面

- 学习计划页标题下加一行成员切换：两个按钮（成员名），选中的高亮；旁边一个「改名」小按钮，用现有的输入对话框改选中成员的名字。
- 切换成员：保存到 `localStorage`（键 `study_member`），并重新加载当前面板。
- 「大计划」面板只列选中成员的计划；新建 / 编辑大计划的弹层里多一个「谁的计划」下拉，新建时默认当前选中的成员；把计划改给另一位成员后，它会从当前列表消失，给出提示「已转给 X」。
- 宽屏沿用上一次的桌面版布局。

### 测试

- `test/smoke.js` 的学习计划块：补成员接口（列表、改名、空名拒绝、不存在 404）；`day`/`month` 缺少或非法 `member` 返回 400；两位成员各建一个计划，`day`/`month`/`plans` 只看到各自的；把计划转给对方后归属跟着变；已有断言里的 `day`/`month` 请求都补上 `member`。
- 纯逻辑 `lib/study.js` 不变。

## 交给构建者决定

- 成员切换按钮的样式；「改名」入口的具体位置。
- 旧库升级时更新 `member_id` 的具体写法，只要保证「旧计划全归第一位成员，且重复启动不会改动已分配的计划」。

## 我替用户做的决定（请核对）

1. 固定两位成员，默认名「我」「TA」，只能改名。
2. 选择记在本机浏览器，不跨设备同步（两人各用各的手机，各自选一次即可）。
3. `day` / `month` 的 `member` 必填，避免漏传时把两个人的计划混在一起显示。
4. 任何人都能切到对方并修改对方的计划（不做权限）。
