## 1. 概览

| 项目 | 说明 |
|---|---|
| 形态 | 一个 Node.js 进程同时提供 **HTTP 接口 + 静态网页**，浏览器单页应用（手机 / 电脑通用，可「添加到主屏幕」） |
| 后端 | Node.js（建议 ≥ 22.13），原生 `http` 模块，自带 SQLite（`node:sqlite`），**零第三方依赖、无需 `npm install`、无构建步骤** |
| 前端 | 原生 JS + 一份 CSS，单页，不使用框架 |
| 存储 | 一个 SQLite 文件 + 一个图片目录 + 一个 JSON 配置文件，全部在 `data/` 下 |
| 认证 | 单一家庭密码，签名 cookie，登录 180 天 |
| 体量 | `server.js` 约 1000 行，`public/app.js` 约 1100 行，`lib/` 8 个模块 |

**设计原则**

1. **零依赖、易部署**：拷贝目录、装好 Node 就能跑，适合树莓派 / NAS / 小云主机。
2. **纯逻辑与副作用分离**：解析、识别、采购计算等逻辑写成无 I/O 的纯函数，放在 `lib/`，用假数据就能离线测试；`server.js` 只做 HTTP 和数据库的薄胶水。
3. **先确认再写库存**：一句话、小票、语音、菜单采购，所有「自动识别」的结果都先进确认卡，由人确认，永远不会直接改库存。
4. **可选功能可关闭**：小票识别和语音识别依赖外部服务，没配置就不显示入口，其余功能不受影响。
5. **密钥不外泄**：识别服务的 key 只存在服务器配置里，不通过任何接口返回，不写日志。

## 4. 后端：`server.js`

文件按「配置 → 数据库 → 工具函数 → 路由 → 服务器」的顺序组织。

### 4.1 启动与配置

- 读取环境变量 `PORT`、`INVENTORY_DATA`（数据目录）、`INVENTORY_PASSWORD`（仅首次建密码）。
- 读取或生成 `data/config.json`：`passwordHash`（scrypt 加盐）、`secret`（会话签名密钥）；可选的 `receipt`、`asr`。读取时对 JSON 语法错误给出固定提示并退出（不打印原文，避免泄露密钥）。
- 小票识别和语音识别的配置**每次使用时**由 `resolveConfig(config.receipt / config.asr, process.env)` 合并得到，环境变量优先；环境变量的值永远不写进内存里的 `config` 对象，所以改密码触发的 `saveConfig()` 不会把它们写回文件。

### 4.2 数据库初始化与升级

启动时用 `CREATE TABLE IF NOT EXISTS` 建表，旧库用 `PRAGMA table_info` 检查后 `ALTER TABLE ADD COLUMN` 补列（如 `locations.plan_id/x/y`、`items.min_quantity/deleted_at`）。**只加不删，升级自动完成。** 打开外键约束（`PRAGMA foreign_keys = ON`）和 WAL 模式。首次运行预置常见位置。

### 4.3 工具函数

| 函数 | 作用 |
|---|---|
| `route(method, pattern, handler)` | 注册路由；`pattern` 是正则，捕获组作为路径参数传给处理函数 |
| `HttpError(status, message)` | 抛出后由统一错误处理转成 `{error: message}`；其他异常按 500 处理 |
| `json` / `send` / `readBody(req, limit)` / `readJson` | 响应与请求体读取（超限抛 413） |
| `readImage(req, limitMB)` | 校验 `image/jpeg\|png\|webp` 并读取图片 |
| `serveFile` | 静态文件，带路径穿越防护 |
| `isAuthed` / `setSessionCookie` | 会话 cookie |
| `allLocations` / `descendantIds` / `findOrCreateLocationPath` / `withPath` | 位置树：带层级路径、含下级的筛选、按路径创建 |
| `cleanItem` | 物品字段校验与规范化（名称必填、数量 ≥ 0、日期格式等） |
| `logStock` | 写变动记录，带来源 |
| `stockItemsForMatch` | 给解析器和小票识别用的「库存匹配列表」（只含未删除的物品） |
| `purgeOldTrash` / `purgeOldMenus` | 清理 30 天前的回收站、约 3 个月前的整周菜单；启动时跑一次，之后每 6 小时 |

### 4.4 请求处理流水线

```
请求 → 解析 URL
  ├─ /api/*   → 非 login/logout/me 必须已登录（否则 401）→ 按路由表匹配 → 处理函数
  ├─ /uploads/* → 必须已登录 → 静态文件（私有、长缓存）
  └─ 其他     → public/ 静态文件（no-cache）；/ 即 index.html
统一 catch：HttpError → {error}；其他异常 → 500 并打印日志
```

## 5. 数据库设计

数据库文件：`data/inventory.db`（SQLite，WAL）。

| 表 | 作用 | 主要字段 |
|---|---|---|
| `locations` | 位置树（房间 → 柜子 → 层 / 抽屉） | `id`、`name`、`parent_id`（级联删除）、`sort`、`plan_id`（所在图纸）、`x`、`y`（图纸上的百分比坐标） |
| `items` | 物品 | `id`、`name`、`category`、`quantity`（REAL）、`unit`、`location_id`（删位置时置空）、`note`、`image`（文件名）、`expires_at`（`YYYY-MM-DD` 或空）、`min_quantity`（最低库存，0 表示不设）、`deleted_at`（空 = 正常，非空 = 在回收站）、`created_at`、`updated_at` |
| `plans` | 户型图纸 | `id`、`name`、`image`、`sort` |
| `stock_log` | 变动记录 | `item_id`、`item_name`、`action`（create / update / quantity / move / delete / restore / purge）、`delta`、`quantity`、`detail`、`source`（manual / quick / receipt / import / list）、`created_at` |
| `shopping_extra` | 购物清单里的手动条目 | `id`、`name`、`note`、`done`、`created_at` |
| `menu_meals` | 菜单的一餐 | `id`、`date`（`YYYY-MM-DD`）、`meal`（breakfast / lunch / dinner）、`UNIQUE(date, meal)` |
| `menu_dishes` | 一餐里的一道菜 | `id`、`meal_id`（级联删除）、`name`、`sort` |
| `menu_ingredients` | 一道菜的一个食材 | `id`、`dish_id`（级联删除）、`name`、`item_id`（关联库存物品，物品被删时置空）、`quantity`（可空）、`unit` |
| `study_members` | 学习计划的成员（固定两位，只能改名） | `id`、`name`、`sort`；首次启动预置「我」「TA」 |
| `study_plans` | 学习计划的大计划 | `id`、`member_id`（所属成员，旧库升级时归第一位）、`name`、`start_date`、`end_date`、`sort`、`created_at` |
| `study_items` | 大计划下的学习项 | `id`、`plan_id`（级联删除）、`name`、`start_date`、`end_date`、`note`、`sort` |
| `study_checks` | 某学习项在某天已学完 | `item_id`（级联删除）、`date`，主键 `(item_id, date)`，重复勾选只留一条 |
| `work_people` | 每周工作的人员 | `id`、`name`、`sort`；首次启动预置「我」；可添加（最多 10 个）、改名，不可删除 |
| `work_entries` | 每周工作的一条记录（只有「已做」） | `id`、`person_id`（级联删除）、`date`、`kind`（现在恒为 `done`）、`text`（≤ 200 字）、`created_at`；`done` 列是旧结构留下的，不再使用 |
| `work_todos` | 每周工作的待办（单独的清单） | `id`、`person_id`（级联删除）、`text`（≤ 200 字）、`due_date`（空串 = 没选日期）、`done`、`done_date`（未完成时恒为空串）、`created_at`；索引 `(person_id, done)` |

**关系**

```
locations 1──* items                    items 1──* stock_log（按 item_id 记录，不设外键，物品清除后日志仍保留）
locations *──1 plans（位置标记在图纸上）   items 1──* menu_ingredients（可选关联）
menu_meals 1──* menu_dishes 1──* menu_ingredients
study_members 1──* study_plans 1──* study_items 1──* study_checks（学习计划；删计划级联删下级，成员不可删）
work_people 1──* work_entries、work_people 1──* work_todos（每周工作；人员不可删）
```

**软删除**：删除物品只是写 `deleted_at`，所有「正常」查询都带 `deleted_at = ''`；回收站查询 `deleted_at <> ''`。数量减到 0 同样自动软删除。

**索引**：`items(location_id)`、`items(category)`、`items(deleted_at)`、`stock_log(item_id)`、`stock_log(created_at)`、`menu_meals(date)`、`menu_dishes(meal_id)`、`menu_ingredients(dish_id)`、`menu_ingredients(item_id)`。

## 7. 接口清单

约定：

- 除 `GET /api/me`、`POST /api/login`、`POST /api/logout` 外，所有 `/api/*` 和 `/uploads/*` 都需要登录 cookie，否则返回 401。
- 成功返回 JSON；失败统一为 `{ "error": "中文提示" }`，状态码见各接口。
- JSON 请求体上限 1MB；图片、音频等二进制请求体在 `Content-Type` 里写明类型。
- 写物品的接口可加 `?source=quick|receipt|list|import` 标注变动记录的来源（不加则为 `manual`）。

### 7.1 认证与设置

| 方法 路径 | 说明 |
|---|---|
| `GET /api/me` | `{authed}`，不需要登录 |
| `POST /api/login` `{password}` | 登录；密码错误会延迟 400ms 再返回 401 |
| `POST /api/logout` | 退出 |
| `POST /api/password` `{oldPassword, newPassword}` | 改密码（新密码 ≥ 4 位）；改完所有设备需重新登录 |

### 7.2 位置与图纸

| 方法 路径 | 说明 |
|---|---|
| `GET /api/locations` | 全部位置（带 `path`、`depth`、物品数） |
| `POST /api/locations` `{name, parent_id}` | 新增位置 |
| `PUT /api/locations/:id` `{name, parent_id, plan_id, x, y}` | 改名 / 移动 / 标记到图纸 |
| `DELETE /api/locations/:id` | 删除（有物品的位置不能删） |
| `POST /api/locations/path` `{path:"书房 / 书架"}` | 按路径逐级查找或创建，返回末级位置 |
| `GET /api/plans` | 图纸列表（带标记数） |
| `POST /api/plans?name=` | 新建图纸，请求体为图片二进制（≤ 20MB） |
| `PUT /api/plans/:id` `{name}` / `POST /api/plans/:id/image` / `DELETE /api/plans/:id` | 改名 / 换图 / 删除 |

### 7.3 物品

| 方法 路径 | 说明 |
|---|---|
| `GET /api/items?q=&category=&location=<id\|none>&expiring=<天数>&low=1` | 查询未删除的物品；`location` 含下级；`expiring` = N 天内到期或已过期；`low=1` = 低于最低库存 |
| `POST /api/items` `{name, category, quantity, unit, location_id, note, expires_at, min_quantity}` | 新增（名称必填，数量 ≥ 0） |
| `PUT /api/items/:id` `{…部分字段}` | 局部更新；数量变为 0 时自动进回收站，返回里带 `auto_deleted` |

### 7.10 每周工作

校验统一：日期必须是真实的 `YYYY-MM-DD`；`kind` 只能是 `done` / `todo`（否则 400「类型无效」）；记录文字去首尾空白后非空、最长 200 字（400「内容不能为空」「内容最长 200 字」）；人员名非空、最长 20 字；人员 id 必须存在（400「人员不存在」）。人员只是分开显示，**不是权限隔离**，同一个密码谁都能看、能改。

| 方法 路径 | 说明 |
|---|---|
| `GET /api/work/people` | 人员列表 → `[{id, name}]` |
| `POST /api/work/people` `{name}` | 添加；最多 10 个（400「人员最多 10 个」） |
| `PUT /api/work/people/:id` `{name}` | 改名；不存在 404「人员不存在」。**没有删除人员的接口** |
| `GET /api/work/week?start=YYYY-MM-DD&person=<id>` | 一周的记录（`start` 自动归一到周一；`person` **必填**，缺失或无效 400）→ `{start, end, days:[{date, entries:[{id, date, text}]}]}`，`days` 恒为 7 天，同一天按记录先后 |
| `POST /api/work/entries` `{person_id, date, text}` | 记一条「已做」。`kind` 可以不传（默认 `done`），传了就必须是 `done`，否则 400「类型无效」且不写入——旧页面误传 `todo` 时不会悄悄写错 |
| `POST /api/work/entries/batch` `{person_id, date, text}`（`kind` 同上） | 语音用：`text` 是未拆分的口述文字，服务端按句号 / 分号 / 换行拆成最多 5 条，整批一个事务；拆不出内容 400「没有可记录的内容」 → `{ids, count, truncated}` |
| `PUT /api/work/entries/:id` `{text?, date?}` | 局部修改，给了的字段才改；传 `kind` 必须是 `done`；`done` 字段不再接受（忽略）；不存在 404「记录不存在」 |
| `DELETE /api/work/entries/:id` | 删除一条 |
| `POST /api/work/entries/delete` `{ids}` | 批量删除（撤销语音记录用），最多 20 个整数 id（否则 400「ids 无效」），不存在的忽略 → `{removed}` |
| `GET /api/work/todos?person=<id>&filter=open\|done\|all` | 待办清单（`person` **必填**；`filter` 默认 `open`，非法 400「filter 无效」）→ `[{id, text, due_date, done, done_date}]`。`open`：有日期的按日期升序、没日期的在后；`done`：按完成日期倒序，**最多 200 条**；`all`：先没做完的再已完成的 |
| `POST /api/work/todos` `{person_id, text, due_date?, done?, done_date?}` | 新建待办；`due_date` 不传或空串 = 没选日期；`done` / `done_date` 只用于「撤销删除」时原样恢复（`done` 为 true 时 `done_date` 缺省取服务器日期，为 false 时强制清空） |
| `PUT /api/work/todos/:id` `{text?, due_date?, done?, done_date?}` | 局部修改；`due_date` 传空串清除日期、不传则不变；`done` 必须是布尔值（否则 400「done 应为 true 或 false」）；勾选时给了 `done_date` 就用它，已完成的保持原完成日期，否则取服务器日期；取消勾选清空 `done_date`；不存在 404「待办不存在」 |
| `DELETE /api/work/todos/:id` | 删除待办；不存在 404「待办不存在」 |
| `GET /api/work/report?start=&person=` | 周报 → `{text, empty}`；本周没有任何「做了什么」（记录和完成的待办都没有）时 `empty` 为 true |

周报内容：「做了什么」= 本周的记录 + 本周**完成**的待办（按完成日期，同一天先记录后待办）；「下周计划」= **全部没做完的待办**（有日期的按日期升序在前，没日期的在后，已过期的也在内）。每周工作是长期记录，**不会自动清理**。

### 7.11 正式周报导出

模板、示例、设置、用量都在 `data/report/`。需要登录；二进制上传（模板、示例）上限 5 MB，以内容为准（必须是合法的 docx zip，解压后 ≤ 30 MB、条目 ≤ 200）。校验失败一律是固定的中文文案。

| 方法 路径 | 说明 |
|---|---|
| `GET /api/report/status` | `{enabled, hasTemplate, examples:[{id, title, chars}], anchor, problem}`。`enabled` = AI 可用（含沿用图片识别的配置）；不返回任何 key |
| `PUT /api/report/settings` `{anchor}` | 基准单休周（真实日期，自动归一到周一） |
| `POST /api/report/template` | 请求体是 docx 二进制。校验结构并**用示例数据试填一次**，通过才保存 → `{ok, name}`（姓名取自抬头）。非 docx 400「不是有效的 docx 文件」，结构不对 400「模板结构不认识：…」 |
| `POST /api/report/examples` | 请求体是 docx 二进制，请求头 `X-Report-Title`（URL 编码）为标题；只抽取文字保存（≤ 6000 字，超出截断），最多保留 4 份，同标题替换 → `{id, chars, truncated}` |
| `DELETE /api/report/examples/:id` | 删除一份示例；不存在 404「示例不存在」 |
| `GET /api/report/dates?start=&today=&kind=` | 大小周日期规则 → `{kind, from, to, time, planRange, filename}`；`today` 用浏览器日期；`kind`（`single` / `double`）可选，给了就用它 |
| `POST /api/report/prepare` `{person, start}` | 组装发给 AI 的完整提示词，**不调用 AI** → `{empty, prompt, hash, chars, examples}`；`hash` 是提示词 SHA-256 的前 32 位。没有模板 409「请先在设置里上传周报模板」 |
| `POST /api/report/generate` `{person, start, hash}` | 服务端**重新组装**提示词并比对指纹，不一致（预览之后记录、待办或示例变了）⇒ 409「内容在预览之后有变化，请重新预览」，**不调用 AI**；一致才调 AI → 草稿 `{items, issues, plan}`。其他：503 未配置 / 429 次数用完或正在整理上一份 / 502 AI 出错 / 504 超时 / 400「这一周还没有记录」 |
| `POST /api/report/export` `{draft, time, planRange, kind, start}` | 严格校验草稿（至少 1 个工作项，标题非空，完成度 0–100 的整数，计划可为空）、`time`（`YYYY.M.D`）、`planRange`（`YYYY.M.D-YYYY.M.D`）、`kind` 后，把内容填进模板，返回 docx 二进制（`Content-Disposition` 带中文文件名）；同时把导出内容存为示例 |

周报整理的每日次数单独记在 `data/report/usage.json`（默认每天 20 次）。

| `receipt.js` | 小票识别纯逻辑：配置解析（环境变量优先、逐项合并）、三种请求格式（`openai` / `anthropic` / `responses`）的构造和回复取值、提示词、回复清洗（容错 JSON、数量清洗、最多 60 项）、**去规格**、生成录入意图（匹配库存 → 补货，否则新增；同一件物品多行合并；单位冲突警告）、重复指纹 | `PROMPT`、`resolveConfig`、`buildRequest`、`extractReplyText`、`parseItems`、`cleanName`、`buildIntents`、`fingerprint` |
| `receipt-service.js` | 小票识别的流程：未配置 → 并发 → 每日上限 → 转发 → 解析 → 重复检测；注入 `fetch` / 时钟 / 目录，可离线测试 | `createReceiptService`、`ReceiptError` |
| `asr.js` | 语音识别纯逻辑：配置解析（含 `maxSeconds`，上限 60）、请求构造（`input_audio`）、回复取值、**识别文字规范化**（两个汉字之间的空白 / 换行变成句号，去引号和前缀，超长按句截断） | `PROMPT`、`resolveConfig`、`buildRequest`、`extractReplyText`、`normalizeTranscript`、`normalizeTranscriptEx` |
| `asr-service.js` | 语音识别的流程：未配置 → 并发 → 每日上限 → 转发 → 解析 | `createAsrService`、`AsrError` |
| `provider-guard.js` | 两个识别服务共用的防护：`callProvider`（超时、响应最多读 2 MiB 且边读边限、HTTP 错误映射成固定中文提示、**日志和错误里不含 key 与响应原文**）、`createUsage`（每日次数，持久化到文件，跨天归零，文件损坏按 0 处理）、`ServiceError` | `callProvider`、`createUsage`、`ServiceError`、`localDate`、`timeoutMs` |

## 9. 核心数据流

### 9.1 一句话录入

```
输入框 / 手机键盘语音
  → POST /api/parse {text}
      parseMulti：按句号拆句 → 每句 parse → 合并意图
        parse：清理 → 判断动作 → mkItems（分隔符拆 → 数量成组拆 → 词表拆）
               → 位置匹配 / 库存匹配 / 分类 / 到期日
  ← {intents, confidence, truncated?}
  → 确认卡（用户核对、可改）
  → 逐条调用 POST/PUT /api/items?source=quick
```

### 9.2 小票录入

```
相机按钮 → 选图 → 浏览器缩放（普通照片最长边 1800；长截图按像素预算）
  → POST /api/receipt/scan（图片二进制）
      receipt-service：未配置?→503  并发?→429  今日上限?→429  计数 +1
        → provider-guard.callProvider → 外部多模态模型
        → receipt.parseItems（清洗） → buildIntents（去规格、匹配库存、合并、单位警告）
        → 重复指纹
  ← {text, intents, duplicate, count}
  → 同一张确认卡（带警告和「疑似重复」提示）→ POST/PUT /api/items?source=receipt
```

### 9.3 语音录入

麦克风按钮有两个：物品页（`data-asr="quick"`）和每周工作页（`data-asr="work"`）。**谁点的麦克风，识别结果就交给谁**；同一时间只有一处在录音，录音中另一个按钮是禁用的，离开发起录音的那个页面就放弃这次录音。物品页走下面的一句话流程，每周工作页的结果直接调用 `POST /api/work/entries/batch` 记到目标日并给「撤销」，不弹确认卡。

```
麦克风按钮（仅 HTTPS + 已配置）→ MediaRecorder 录音
  → decodeAudioData → 声道平均 → WavEnc.encode（16kHz 单声道，最长 maxSeconds）
  → POST /api/asr/transcribe（audio/wav）
      asr-service：同上防护 → 外部模型听音频 → normalizeTranscript
  ← {text, truncated?}
  → 填进一句话输入框 → 走 9.1 的流程
```

### 9.4 每周菜单与采购

```
点某一餐 → 编辑弹层 → PUT /api/menu/meal（整餐替换）
「按本周菜单生成采购」
  → POST /api/menu/purchase/preview {start}
      读本周所有菜和食材 → menu.computePurchase（对照库存）
  ← {need, enough, exists} → 确认卡（三组，默认勾选「需要买」）
  → POST /api/menu/purchase {lines}   → shopping_extra（不改库存）
```

### 9.5 学习计划

```
大计划 → 学习项（各有起止日期）→ 每天勾选
打开「今天」→ GET /api/study/day?date=&member=（只含该成员的计划，「即将开始」也一样）
    读全部学习项 → study.itemsOnDate（覆盖当天）→ study.progress（第几天、已学、已落下）
    → study.upcoming（即将开始，最多 3 项）
点勾选 → PUT /api/study/check（日期必须在该项范围内）→ 重新取当天
```

落下的日子只显示，不自动重排或顺延；日期由用户自己改，改日期不会丢勾选。

### 9.6 每周工作

```
进入页面 → GET /api/work/people（选中的人记在 localStorage 的 work_person，已不存在则回退第一位）
         → GET /api/work/week?start=&person=
打字回车 → POST /api/work/entries（记到「目标日」：浏览的周含今天就是今天，否则是周一；点某天标题可改）；每一天的「＋」→ 行内输入 → 记到那一天；「×」→ DELETE → 「撤销」= 用原日期重新 POST
说一段话 → 语音识别 → POST /api/work/entries/batch → 「已记录 N 条」+ 撤销（POST /api/work/entries/delete）
「待办」标签 → GET /api/work/todos?person=&filter=（默认 open）；添加（日期可不选）→ POST /api/work/todos；勾选 → PUT {done, done_date: 今天}
挪到下周 → PUT /api/work/todos/:id {due_date: 「原日期和今天较晚者」所在周的下一周周一}
生成周报 → GET /api/work/report（记录 + 本周完成的待办 + 全部未完成待办）→ 弹层里的文本框，可编辑后复制
```

### 9.7 正式周报导出

```
设置页上传模板 → POST /api/report/template（校验结构 + 试填一次）→ data/report/template.docx
设置页上传示例 → POST /api/report/examples（只抽取文字存下）→ data/report/examples/<id>.json（最多 4 份）

记录页「整理成正式周报」
  → POST /api/report/prepare {person, start}
      reportInputs：本周记录 + 本周完成的待办 + 全部没做完的待办 + 示例 → report-ai.buildPrompt
  ← {prompt, hash}                    弹层 A：用户看到将发送的完整内容
  → POST /api/report/generate {person, start, hash}
      服务端重新组装提示词 → 指纹与 hash 不一致 ⇒ 409（不调用 AI、不占次数）
      → 并发 / 每日限额 → provider-guard.callProvider → 外部 AI → parseDraft（容错取 JSON，规整、截断）
  ← 草稿 {items, issues, plan}
  → GET /api/report/dates?start=&today=（today 取浏览器日期）→ 大小周规则算出 time / planRange / filename
  弹层 B：用户修改草稿，可切换本周单休 / 双休（重新算计划日期和文件名）
  → POST /api/report/export {draft, time, planRange, kind, start}
      validateDraft（严格）→ report-docx.fillTemplate（复制样板行、重置编号、行高改最小行高、替换签名日期）
      → 返回 docx；同时把导出内容存为示例
```

### 9.8 后台清理

启动时和每 6 小时：删除回收站里超过 30 天的物品（及其图片）；删除整周都早于「今天往前推 3 个月再减 1 天所在周的周一」的菜单（级联删除菜和食材）。

## 10. 前端结构

### 10.1 页面骨架（`index.html`）

- **登录页** `#login` 和**主界面** `#app`（物品页：顶部栏、一句话输入框、统计条、物品列表、添加按钮）。
- **子视图**（`class="screen subview"`，同一时间只显示一个）：`#view-home`（首页）、`#view-tools`（工具页）、`#view-menu`（每周菜单）、`#view-study`（学习计划）、`#view-work`（每周工作）、`#view-shopping`（购物清单）、`#view-plans`（图纸）、`#view-locations`（位置）、`#view-settings`（设置）。
- **底部标签栏**：首页 / 物品 / 清单 / 图纸 / 位置 / 设置。工具页和菜单页不在标签栏里，进入时没有任何标签高亮。
- **弹层**：`#editor`（物品编辑）、`#confirm`（录入确认卡，一句话 / 小票 / 语音共用）、`#menu-editor`（编辑一餐）、`#menu-purchase-sheet`（采购确认）、`#dialog`（通用对话框，代替浏览器自带的 prompt / confirm）、`#toast`（提示）。
- 顶部有一个 SVG 图标「精灵表」（`<symbol id="i-…">`），页面里用 `<use href="#i-…">` 复用。

### 10.2 `app.js` 的分区

单个文件、一个立即执行函数，按注释分区：

| 分区 | 内容 |
|---|---|
| 工具 | `api()`（统一的 fetch 封装，401 回登录页）、`postJson`、`toast`、`esc`（HTML 转义） |
| 登录 / 启动 | 登录、`enterApp`（加载数据，并探测小票和语音是否可用）、启动入口 |
| 加载数据 | 位置、分类、统计、物品列表、变动记录 |
| 编辑器 | 物品新增 / 编辑、图片压缩上传 |
| 快速录入 | `runQuick`（一句话解析流程）、`showConfirm`（确认卡）、确认后的写库存 |
| 拍小票录入 | 选图 → 缩放 → 上传 → 确认卡 |
| 语音录入 | 录音状态机（idle / starting / recording / busy），`asr.target` 记录是物品页（`quick`）还是每周工作页（`work`）发起的；解码、转 WAV、上传；结果按 `target` 分发：物品页填入输入框走一句话流程，每周工作页直接记录并可撤销 |
| 视图切换 | `switchView` |
| 每周菜单 | 取周、渲染日历、编辑一餐、联想、采购确认 |
| 学习计划 | 成员切换（选择存 `localStorage` 的 `study_member`，已不存在则回退第一位）、今天 / 按月看 / 大计划三个面板，新建编辑弹层（大计划和学习项共用，大计划多一个「谁的计划」），勾选 |

| 正式周报 | 设置页：状态、上传模板 / 示例、示例列表、基准单休周；每周工作页：按钮（AI 不可用或没模板时置灰并说明原因）、预览弹层（将发送的完整内容）、草稿弹层（单休 / 双休切换、项目 / 细节 / 完成度 / 计划的增删改）、导出（用 `fetch` 取二进制后触发下载，文件名取自响应头）；AI 返回的文字只通过 `.value` / `.textContent` 进入页面 |
| 首页 / 购物清单 / 图纸 / 位置 / 设置 | 各自的渲染和事件 |

**确认卡**是三种快捷录入共用的出口：`showConfirm(r)` 接收 `{text, intents, source?, notice?, note?}`，写库存时按 `source`（`quick` / `receipt`）给接口加 `?source=`，变动记录里就能看出来源。

### 10.3 前端辅助模块（浏览器和 Node 通用）

| 模块 | 全局名 | 作用 |
|---|---|---|
| `menu-cal.js` | `MenuCal.render(week, today)` | 把一周数据渲染成日历网格的 HTML 字符串（转义、`+N`、无障碍文字、今天高亮） |

### 10.4 样式（`style.css`）

- 「温润家居极简」风格：暖色背景、陶土色主色、柔和阴影、统一圆角，线性 SVG 图标。

## 11. 安全设计

| 方面 | 做法 |
|---|---|
| 密码 | scrypt 加盐哈希，常数时间比较；错误密码延迟 400ms 返回 |
| 会话 | cookie `inv_session`，`HttpOnly`、`SameSite=Lax`、180 天；令牌 = HMAC(`secret`, `passwordHash`)，所以**改密码即让所有会话失效** |
| 接口 | 除登录相关外全部需要登录；图片（`/uploads/`）也需要登录 |
| 文件 | 静态文件路径穿越防护；上传限制类型和大小（物品图 15MB、图纸 20MB、小票 8MB、录音 2MB、JSON 1MB） |
| 输入 | 所有 SQL 参数化；前端渲染一律经 `esc()` 转义，识别结果也一样 |
| 识别服务 key | 只在服务器配置里；任何接口都不返回；不写日志；错误提示是固定的中文，不回显识别服务的响应原文；日志只记状态码 |
| 周报导出 | 模板、示例、设置、用量只在 `data/report/`（不进 git）；提示词里的内容每次发送前都让用户预览，并用指纹保证发出去的就是预览的；上传的 docx 限 5 MB、解压后 ≤ 30 MB、条目 ≤ 200，拒绝加密和 zip64；示例 id 只接受纯数字，不会拼出路径；日志和错误响应里不含 key、提示词和周报内容；周报单独配了地址时不沿用图片识别的 key |
| 花费保护 | 两个识别服务各有每日次数上限（持久化）、同时只处理一个请求、超时、响应读取上限 |
| 配置文件 | 语法错误时只打印固定提示（防止把 `secret` 或 key 打进日志） |
| 传输 | 应用本身是 HTTP；**公网使用请放在 Nginx / Caddy 之后加 HTTPS**（语音录入也要求 HTTPS） |

## 13. 扩展指南

| 想做什么 | 改哪里 |
|---|---|
| 一句话里加一个分类关键词 | `lib/parse.js` 的 `CATEGORY_KEYWORDS`（靠前的分类优先） |
| 让某个名称在一句话里不被拆开，或能被拆开 | `lib/vocab.js`：整体名称加进末尾的 `COMPOUND`；常见物品加进对应类别（单字词只允许一小组，见文件注释） |
| 加一个位置别名（如「门口」→「玄关」） | `lib/parse.js` 的 `LOCATION_ALIASES` |
| 支持更多数量单位 | `lib/parse.js` 的 `UNIT_RE` |
| 换识别服务 / 换模型 | 只改 `data/config.json` 或环境变量，不改代码 |
| 支持新的识别接口格式 | 小票：`lib/receipt.js` 的 `buildRequest` / `extractReplyText`；语音：`lib/asr.js` 同名函数，并在各自的 `resolveConfig` 里把格式加入允许列表，补测试 |
| 加一个新的小工具（像每周菜单那样） | `public/index.html` 加视图；`app.js` 的 `switchView` 加一行并写渲染；工具页 `#view-tools` 加入口卡片；需要存数据就在 `server.js` 加表和接口 |
| 加一个新接口 | `server.js` 用 `route(...)` 注册；需要的纯逻辑放 `lib/`、配测试；要写物品就调用 `logStock` 记变动 |
| 数据库加字段 | 在启动升级段用 `PRAGMA table_info` 检查后 `ALTER TABLE ADD COLUMN`，保证旧库自动升级 |

## 14. 已知限制

- **单用户、单密码**：没有账号体系，所有人共用一个家庭密码和同一份数据。
- **应用不处理 HTTPS**：需要在前面放 Nginx / Caddy；语音录入因此依赖 HTTPS。
- **解析器是规则，不是 AI**：词表里没有的词不会被拆；两个词表里的词写在一起但其实是一个产品时可能被拆开（遇到就在确认卡上改，或补词表）。
- **识别结果不保证准确**：所以永远先确认；小票上没有位置和到期日，需要手动选；日期不使用识别出的值。
- **每个识别服务一次只处理一个请求，且有每日次数上限**（可配置）。
- **语音录入第一版只支持火山方舟的 Responses 接口**；不同手机浏览器录出来的音频格式不同，个别旧浏览器可能解码失败。
- **菜单**：整餐替换，两个人同时改同一餐，后保存的覆盖先保存的；菜单不会扣库存。
- **重复检测**只保存在内存里，服务重启后丢失。
- **数据库是单文件 SQLite**，不适合多机并发写；备份要整个复制 `data/`。

- **周报导出无法在真实的 Word 里自动验证**：靠测试检查输出的 zip 和 XML 结构，最终要在 Word 里人工打开确认；只支持 `.docx`，不支持老式 `.doc`；一份模板、模板里的姓名不随「人员」变；AI 的内容不保证准确，必须人工核对。
