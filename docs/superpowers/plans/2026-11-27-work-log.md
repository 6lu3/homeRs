# 每周工作记录 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在「日常工具」里增加「每周工作」：按周记录每天做了什么和待办，支持打字和语音，一键生成周报；数据按人员分开，可添加人员。

**Architecture:** 纯逻辑放 `lib/work.js`（拆句、下周一、周报，离线测试）；`server.js` 新增两张表和 `/api/work/*`；前端加 `#view-work` 与「每周工作」一节；最后把现有语音录入改造成物品页和本页都能用。

**Tech Stack:** Node ≥ 22 + `node:sqlite`，原生 JS，零第三方依赖。

**Spec:** `docs/superpowers/specs/2026-11-27-work-log-design.md`

## Global Constraints

- 零第三方依赖；错误统一 `{error: "中文提示"}` + `HttpError`；周计算复用 `lib/menu.js` 的 `weekStart` / `addDays`，不另写。
- 日期一律 `YYYY-MM-DD`；非法日期提示固定为「日期格式应为 YYYY-MM-DD」。
- 记录文字去首尾空白后非空、最长 200 字；人员名去首尾空白后非空、最长 20 字（按字符数 `[...s].length` 计）、最多 10 人。
- 校验文案固定：「人员不存在」「名称不能为空」「名称最长 20 字」「人员最多 10 个」「内容不能为空」「内容最长 200 字」「类型无效」「没有可记录的内容」。
- `person` / `person_id` 必须是存在的人员，否则 400「人员不存在」（`PUT /people/:id` 对不存在的 id 为 404「人员不存在」）。
- 不启动测试服务器或浏览器；冒烟测试只写不跑；前端靠 `node --check`；每个任务结束前对改动过的 JS 文件跑 `node --check`。
- **物品页现有语音录入的行为不能变。**
- 不做：AI 总结周报、分类标签、提醒、导出、删除人员、权限隔离、自动清理。

## Review Focus

- 日期：目标日跨周、跨年；周日的待办「挪到下周」得到下一周周一（`2026-11-29` → `2026-11-30`）；改记录日期后它出现在新日期所在周、从旧周消失。
- 人员隔离：`week`/`report` 缺 `person`、非数字、不存在都是 400，不是 500；一个人的记录绝不出现在另一个人的周视图和周报里。
- 批量与撤销：批量记录整批在一个事务里（有一条非法则整批不写）；撤销一批只删这一批的 id，不波及其他记录；识别文字为空、全是标点、超过 5 句时的行为（超出部分不记并提示）。
- 周报：已勾选完成的待办算「本周做了什么」；把类型改回「已做」后 `done` 被重置；整周为空时不生成；周报里没有未转义问题（它是纯文本，前端用 `textarea.value` 赋值）。
- 前端：翻周 / 切换人员时旧请求回包不污染当前画面（seq）；所有拼进 `innerHTML` 的用户文本都经 `esc()`；录音时离开页面会放弃录音；两个麦克风按钮同一时间只有一处在录音。

**Interfaces:**

- Produces（`module.exports`）：
  - `splitSpoken(text: string, max: number = 5): { parts: string[], truncated: boolean }` — 按 `。！？；;` 和换行（含 `!` `?` 半角）拆句，每段去首尾空白，丢弃空段；`parts` 最多 `max` 条，多于 `max` 条时 `truncated` 为 `true`（只保留前 `max` 条）。`text` 非字符串当空串。
  - `nextMonday(date: string): string` — 该日期所在周的下一周周一。
  - `buildReport({ start, entries, nextWeekTodos }): { text: string, empty: boolean }`
    - `start`：本周周一；`entries`：本周记录 `[{date, kind, text, done}]`（输入顺序即同一天内的显示顺序）；`nextWeekTodos`：日期落在下一周的**未完成**待办 `[{date, text}]`（由调用方筛好）。
    - 「做了什么」条目 = `kind === 'done'` 或 `done` 为真的待办。「下周计划」条目 = `entries` 里 `kind === 'todo'` 且未完成者（输入顺序）+ `nextWeekTodos`（按 `date` 升序，同日保持输入顺序）。
    - `entries` 为空数组 ⇒ `{ text: '', empty: true }`。否则 `empty: false`，`text` 为下列行用 `\n` 连接（没有空行、末尾无换行），无内容的日子和无内容的「下周计划」整段省略：
      ```
      本周工作（11/23 – 11/29）
      周一
      - 对接 A 项目接口
      周二
      - 修了登录 bug
      - 开周会
      下周计划
      - 整理测试报告
      ```
      标题日期为 `M/D`（不补零），中间是 `U+2013` 破折号两侧各一个空格；星期用「周一…周日」；条目前缀 `- `。

### Task 2: 数据库、接口与冒烟测试

**Files:**
- Modify: `server.js`（菜单 / 学习计划建表块之后加建表；学习计划路由段之后加 `/api/work/*`）
- Modify: `test/smoke.js`（学习计划块之后、「清理」之前加工作记录块）

**Interfaces:**
- Consumes: Task 1 的 `lib/work.js`；`lib/menu.js` 的 `weekStart` / `addDays`；`server.js` 里已有的 `route`、`HttpError`、`readJson`、`json`、`db`、`study.isDate`（用它校验日期）。
- Produces（HTTP，均需登录）：
  - 表 `work_people(id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL, sort INTEGER NOT NULL DEFAULT 0)`；`work_entries(id INTEGER PRIMARY KEY AUTOINCREMENT, person_id INTEGER NOT NULL REFERENCES work_people(id) ON DELETE CASCADE, date TEXT NOT NULL, kind TEXT NOT NULL, text TEXT NOT NULL, done INTEGER NOT NULL DEFAULT 0, created_at TEXT NOT NULL)`；索引 `work_entries(person_id, date)`。启动时 `work_people` 为空则在一个事务里预置一行「我」。
  - `GET /api/work/people` → `[{id, name}]`（按 `sort, id`）。
  - `POST /api/work/people` `{name}` → `{id, name}`；`sort` 取当前最大值 + 1。
  - `PUT /api/work/people/:id` `{name}` → `{id, name}`。
  - `GET /api/work/week?start=&person=` → `{start, end, days:[{date, entries:[{id, kind, text, done: boolean, date}]}]}`，`days` 恒为 7 天，同一天按 `id` 升序；`start` 缺失或非法 400。
  - `POST /api/work/entries` `{person_id, date, kind, text}` → 新建行 `{id, person_id, date, kind, text, done: false}`。
  - `POST /api/work/entries/batch` `{person_id, date, kind, text}` — `text` 是**未拆分的原始口述文字**，服务端用 `splitSpoken(text, 5)` 拆成多条（单条超 200 字 400「内容最长 200 字」），整批一个事务；拆不出任何内容 400「没有可记录的内容」；返回 `{ids:[…], count, truncated}`。
  - `PUT /api/work/entries/:id` `{text?, kind?, date?, done?}` — 局部修改，给了的字段才校验并修改；`done` 必须是布尔值（否则 400「done 应为 true 或 false」）；`kind` 改成 `done` 时 `done` 重置为 0；不存在 404「记录不存在」；返回更新后的行。
  - `DELETE /api/work/entries/:id` → `{ok:true}`（不存在 404「记录不存在」）。
  - `POST /api/work/entries/delete` `{ids:[…]}` — `ids` 必须是整数数组且 ≤ 20 个（否则 400「ids 无效」），不存在的忽略 → `{removed}`。
  - `GET /api/work/report?start=&person=` → `{text, empty}`：取该人员本周记录（按 `date, id`）和下一周里**未完成**的待办（按 `date, id`），交给 `buildReport`。
