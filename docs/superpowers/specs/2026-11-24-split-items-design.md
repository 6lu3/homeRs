# 一句话录入：自动拆分一串物品 设计（小改动）

日期：2026-11-24　状态：设计已向用户讲解并认可

## 意图与原因

用户说「今天买了牛肉猪肉猪肉丝排骨」（语音识别出来没有任何分隔符），现有解析器只在遇到「、，,;和跟以及还有与加上外加」时才拆项，结果整串变成一个物品「牛肉猪肉猪肉丝排骨」。用户希望自动分项。

实测还发现同类问题：「买了两斤牛肉三斤排骨」被解析成一项「牛肉三斤排骨 ×2斤」。

## 目标

- 没有分隔符的一串常见物品名，自动拆成多项：「今天买了牛肉猪肉猪肉丝排骨」→ 牛肉、猪肉、猪肉丝、排骨。
- 「数量 + 单位」成组出现的，每组一项：「买了两斤牛肉三斤排骨」→ 牛肉 2 斤、排骨 3 斤。
- 语音识别的提示词要求模型在不同物品之间加「、」（模型自己知道词边界，最准）。
- 现有所有解析用例的结果不变。

## 非目标 / 反目标

- 不接入任何 AI 或网络，解析仍是纯规则、离线。
- 不拆词表里没有的词；不做拼音、分词模型、统计方法。
- 反目标（即使看起来能用也算失败）：把一个整体的物品名拆坏（「三鲜水饺」「牛肉面」「5号电池」不能被拆）。宁可不拆，也不乱拆。

## 约束

- 零第三方依赖；沿用 `lib/parse.js` 的风格和 `test/parse.test.js` 的测试方式。
- `parse()` 对没有触发新规则的句子，返回必须与改动前完全一致（现有用例全部保持通过，`parseMulti` 与 `parse` 的一致性检查也保持通过）。

## 已考虑的做法

- 只改语音识别的提示词：对手机键盘语音和打字无效。
- 用大模型来解析整句：要联网、花钱、变慢，违背一句话录入「纯规则、不联网」的定位。
- **词表切分 + 数量成组切分 + 提示词（已选）**：三层互补，纯规则部分离线可用。

## 已定的设计

### 1. 数量成组切分（不需要词表）

对按现有规则（`、，,;；和跟以及还有与加上外加`）拆出来的每一段，再检查里面有几处「数量 + 单位」（沿用现有的 `NUM_RE`、`UNIT_RE`，并沿用 `NOT_QTY_AFTER` 排除「5号」「3M」这类不是数量的情况）：

- 少于 2 处：不处理。
- 段首就是一处数量（数量在前，如「两斤牛肉三斤排骨」）：从每处数量开始切一段，每段必须在数量后面还有名称，否则整段不拆。
- 段首不是数量、且最后一处数量正好在段尾（数量在后，如「牛肉两斤排骨三斤」）：每段到一处数量为止，每段必须在数量前面有名称，否则整段不拆。
- 其他布局（混合、有多余文字）：不拆。

### 2. 词表切分

对数量成组切分后**不含任何「数量 + 单位」**的每一段，如果它能被词表完整切开：

- 词表 = 内置常见物品词表（新文件 `lib/vocab.js` 导出 `COMMON_ITEMS`）∪ 当前库存里的物品名（去掉空白，长度至少 2；通过现有的 `ctx.items` 传入，每次解析构造一次）。
- 只在整段都能被词表切开、且至少切出 2 个词时才拆；否则整段原样保留（保守）。
- 在所有能完整切开的方案里，选**词数最少**的；词数相同时，优先靠前的词更长。所以词表里有「牛肉面」时「牛肉面」保持一项；「牛肉猪肉猪肉丝排骨」得到 牛肉 / 猪肉 / 猪肉丝 / 排骨。
- 含有「数量 + 单位」的段不做词表切分（如「牛肉猪肉两斤」：数量属于谁说不清，保持一项）。
- （终审后补）切出的**最后一个词若是单字**，整串不拆：花生米、葡萄酒、牛奶糖、柠檬茶、红糖姜茶这类「某料 + 单字」多半是一个整体名称。代价：「牛肉鱼」这样以单字结尾的清单也不拆。
- （终审后补）词表切分之前，先对这一段做 `cleanName`（去掉「点」「一些」「昨天买的」「了」这类说话时带的开头和结尾），否则「买了点牛肉猪肉」会因为多了个「点」整串切不开。
- （终审后补）「口味/馅料 + 产品」这一类（草莓酸奶、猪肉白菜水饺、猪肉包子……）数量无穷，词表里只收了常见的；遇到被拆坏的，把整词加进 `lib/vocab.js` 末尾的 `COMPOUND`，或者在确认卡上手动改。库存里已有的完整名字也会让它保持一项。

### 3. 内置词表 `lib/vocab.js`

- `COMMON_ITEMS`：字符串数组，至少 300 个、不重复、不含空白，覆盖：肉类（牛肉、猪肉、猪肉丝、排骨、五花肉、鸡肉、鸡翅、羊肉…）、水产（鱼、虾仁、三文鱼…）、蛋奶豆制品（鸡蛋、牛奶、酸奶、豆腐…）、蔬菜、水果、主食和干货（大米、面条、挂面、粉丝、面包、饺子、花生…）、饮品、调料、日用品（纸巾、洗衣液、电池、创可贴…）。
- 单字词只允许这一小组：鱼、虾、蛋、米、葱、姜、蒜、梨、桃、枣、盐、糖、醋、酒、茶（单字词容易误拆，不要加「面」「粉」这类容易构成合成词的字）。
- 放在单独文件里，用户可以随时增删。

### 4. 语音识别提示词

`lib/asr.js` 的 `PROMPT` 增加规则：一次说了多种物品时，物品之间用顿号「、」隔开（并给一个例子，如「买了牛肉、猪肉、排骨」）。「、」不是句子分隔符，不受 `normalizeTranscript` 影响。

### 5. 接入点

`lib/parse.js` 里 `mkItems` 目前用 `splitItems(phrase)`；改为对每一段依次做数量成组切分、词表切分，得到最终的物品字符串列表，再走现有的数量提取和 `cleanName`。词表在 `parse()` 开头根据 `ctx.items` 构造一次。

## 交给构建者决定

- 词表里具体收哪些词（按上面的类别和单字词规则整理，宁缺勿滥）；新增函数放在 `lib/parse.js` 还是拆出去（不要让 `vocab.js` 反过来依赖 `parse.js`）。
- 词表切分用动态规划实现即可，输入最长几十个字，性能不是问题。

## 我替用户做的决定（请核对）

1. 一串里只要有一个词不在词表里，整串都不拆（保守）。
2. 词数最少优先，所以词表里有的合成词（牛肉面）保持整体。
3. 含数量的段不做词表切分。
4. 内置词表只覆盖常见物品，库存里已有的名字会自动加入。
5. （终审后）末尾单字保护、切分前先清洗、补充常见合成词，见「词表切分」一节。
6. （终审后）顺带修了一个原有的缺陷：数量单位后面紧跟「米」「年」时（一袋米、五斤米、两箱年糕）原来会被当成不是数量，整句变成一个名叫「一袋米」的物品。现在「数量 + 单位」后面只有「月」和英文字母会让它不算数量（「三个月」是时长）。这改变了 `extractQuantity` 的一个判断，但只放宽了「米」「年」。
