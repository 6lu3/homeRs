# 语音录入（页面里的麦克风按钮）设计

日期：2026-11-24　状态：设计已向用户讲解并认可，待用户审阅本文档

## 意图与原因

一句话录入目前靠手机键盘上的麦克风把语音转成文字。用户希望页面里有一个专用的说话按钮：点一下说话，再点一下结束，服务器识别出文字后直接进入现有的确认卡。

用户已用真实录音验证：火山方舟的 Responses 接口可以让 `doubao-seed-2-1-lite-260915` 听音频并转写（`input_audio` + `audio_url` 传 `data:` URL，关闭思考），一段 136KB 的 m4a 耗时 1.3 秒，用量约 130 个 token，识别出「把鸡蛋放入冰箱冷藏 买了五花肉一盒」。

使用者：全家人，主要在手机上用。站点已是 HTTPS（浏览器只在安全页面允许录音）。

## 目标

- 物品页一句话录入旁有一个麦克风按钮：点一下开始录音，再点一下结束（最长 30 秒自动结束）。
- 录音在浏览器里转成 16kHz 单声道 16 位 WAV，上传服务器，服务器转发给语音识别服务，返回文字。
- 文字填进一句话录入输入框，并自动解析，弹出现有的确认卡；用户核对、可修改后再保存。
- 一口气说多件事（如「把鸡蛋放入冰箱冷藏，买了五花肉一盒」）时，每件事都要被识别出来。
- 语音识别的配置与小票识别完全分开（独立的配置、独立的每日次数计数）。

## 非目标 / 反目标

- 不做持续监听、唤醒词、边说边出字（流式）、说话人识别。
- 第一版只支持已验证的方舟 `responses` 格式；其他服务商的格式以后按需加，不在本次范围。
- 不保存录音；不做录音回放。
- 不使用浏览器自带的 Web Speech API（在国内不可靠）。
- 不做本地识别（sherpa-onnx 等）；本设计只保证以后可以通过 `format` 扩展，不实现。
- 反目标（即使功能看起来能用也算失败）：未经确认卡就改动库存；key 出现在任何接口响应、日志或前端；识别服务出问题时拖垮其他功能；无上限地花钱；一口气说多件事时悄悄丢掉后面的。

## 约束

- 零第三方依赖；Node ≥ 22.5；用 Node 自带 `fetch`；前端原生 JS。
- 沿用现有风格与结构：`lib/` 放纯逻辑，`server.js` 放很薄的接口胶水，`public/` 放前端，测试放 `test/`，全部可离线测试（假 `fetch`、临时目录、可控时钟）。
- 所有新接口走现有登录检查；key 只存在于服务器配置，不通过任何接口返回，不写日志，错误信息里也不能出现 key 或识别服务的响应原文。
- 环境变量的值永远不写回 `config.json`；改密码重写配置后，文件里原有的 `asr` 字段必须保留。
- 与小票识别的防护规则一致：只读最多 2 MB 的响应（边读边限，超限立即中止并取消）、超时用整数毫秒且有上限、HTTP 出错时丢弃响应体、同一时间只处理一段、用量持久化。
- 界面文字和错误提示全部用中文；所有来自识别结果的文字渲染时必须转义。

## 已考虑的做法

- **A. 用方舟的多模态大模型听音频（已选）**：已实测可用、很快很便宜，和小票同一类配置。
- B. 专门的语音识别产品（火山引擎语音技术、阿里云、腾讯云、百度等）：中文准，但是另一个账号、另一套 key 和接口，第一版不做。
- C. 本地 sherpa-onnx：免费且录音不出服务器，用户的服务器（2 核、1.8GB、x86_64）看起来跑得动，但要单独安装程序和几百 MB 模型，不符合「只需 Node.js」；留作以后通过 `format` 扩展。
- D. 浏览器自带的 Web Speech API：国内安卓 Chrome 依赖 Google 服务，不可靠。

## 已定的设计

### 配置（`lib/asr.js` 的 `resolveConfig`）

- `config.json` 的 `asr` 对象：`{ url, key, model, format, extra, timeoutSec, dailyLimit, maxSeconds }`。
- 环境变量（优先于配置文件，逐项覆盖；`ASR_EXTRA` 整体替换文件里的 `extra`）：`ASR_API_URL`、`ASR_API_KEY`、`ASR_MODEL`、`ASR_FORMAT`（第一版只有 `responses`，默认 `responses`）、`ASR_EXTRA`（JSON 对象，合并进请求体最外层，如 `{"thinking":{"type":"disabled"}}`）、`ASR_TIMEOUT_S`（默认 30，允许小数）、`ASR_DAILY_LIMIT`（默认 100，0 表示不限）、`ASR_MAX_SECONDS`（单段录音最长秒数，默认 30；若识别服务拒绝较长的录音，调小它即可）。
- `url`、`key`、`model` 三项齐全才算已配置；`ASR_EXTRA` 不是合法 JSON 对象、`format` 不支持时视为未配置，启动日志提示原因（不含 key）。三项只配了一部分时，提示缺少哪几项。
- 用量计数存在 `data/asr-usage.json`（`{ date, count }`，与 `receipt-usage.json` 互不影响；日期按服务器本地日期，与小票一致）。
- `DEPLOY.md` 补充语音识别配置小节（写法与小票一致：推荐 `config.json` + `chmod 600`，或 root 专属的环境变量文件）。

### 请求与回复（已用真实服务验证）

- `POST <url>`，头 `authorization: Bearer <key>`，`content-type: application/json`。
- 体：`{ ...extra, model, input: [{ role: 'user', content: [{ type: 'input_text', text: PROMPT }, { type: 'input_audio', audio_url: 'data:audio/wav;base64,<数据>' }] }] }`；`extra` 不能覆盖 `model` 与 `input`。
- 回复文字：取 `output` 里所有 `type:'message'` 项的 `content` 中 `type:'output_text'` 的拼接。
- 提示词必须包含的规则：逐字转写，只返回文字，不加解释；这是家庭物品录入的口语（给几个例句：买了两盒酸奶放冷藏、把电钻放到车库的工具架上、创可贴用完了）；几件互相独立的事用句号「。」隔开；不要在句子中间加空格；数字用阿拉伯数字。具体措辞交给构建者。

### 接口

- `GET /api/asr/status` → `{ enabled: boolean, maxSeconds: number }`（需登录）。前端用 `maxSeconds` 决定自动结束录音的时间。
- `POST /api/asr/transcribe`：请求体是 WAV 二进制，`Content-Type: audio/wav`，最大 2 MB；成功返回 `{ text: string }`（已规范化，见下）。识别出空文字时返回 200 和 `{ text: '' }`。
- 错误统一为中文提示，不回显识别服务响应原文：503「语音识别未配置」（先于读取请求体）、415「仅支持 WAV 录音」、413「录音太长」、429「今天的语音识别次数用完了」或「正在识别上一段，请稍等」、504「识别超时」、502「连不上识别服务，请稍后再试」、502「识别服务拒绝了请求，请检查服务器上的 key」（识别服务返回 401/403）、502「识别服务出错（HTTP <状态码>），请稍后再试」、502「识别服务返回了无法理解的内容，请再说一遍」。
- 执行顺序、计数、进行中标志、错误清除方式与小票识别一致：未配置 → 并发检查 → 每日上限检查 → 计数 +1 并立即持久化 → 转发；无论成败都清除「进行中」；失败的调用也计数。每日上限默认 100。
- 接口层的检查顺序：登录 → 未配置（503，不读请求体）→ 类型（415）→ 读取请求体并限制 2 MB（413）→ 交给服务（并发 429 → 每日上限 429 → 计数 → 转发）。**415、413 以及读取请求体中途断开都发生在计数之前，不消耗次数**；只有真正转发给识别服务的请求才计一次。
- 语音识别服务与小票识别服务各自维护自己的「进行中」标志和用量，互不阻塞：同一时间可以一边识别小票、一边识别语音。

### 识别文字的规范化（纯函数 `normalizeTranscript(text)`）

- 去首尾空白；去掉模型可能加的首尾引号和「识别结果：」之类的前缀不要求，但不得保留换行：换行当作句子分隔（变成「。」）。
- 两个汉字之间的空白（含全角空格）当作句子分隔，替换为「。」；数字或字母旁边的空白不动（避免把「2 盒」拆开）。
- 连续的句子分隔符合并为一个；去掉首尾的分隔符；最长保留 200 个字符（与输入框一致）。
- 例：`'把鸡蛋放入冰箱冷藏 买了五花肉一盒'` → `'把鸡蛋放入冰箱冷藏。买了五花肉一盒'`；`'买了 2 盒酸奶'` 保持不变。

### 一口气说多件事（`lib/parse.js` 新增 `parseMulti(text, ctx)`）

- 背景：现有 `parse()` 在匹配前会先去掉所有「！!。？?～~」和空白，所以含句号的多句话会被当成一句、只认出前半。实测「把鸡蛋放入冰箱冷藏。买了五花肉一盒」只得到一条意图。
- `parseMulti` 先按「。！!？?；;」和换行把原文拆成句子（去空白，丢弃空句，最多 5 句，多的丢弃），对每句调用 `parse(句子, ctx)`，把所有意图按顺序合并，返回与 `parse()` 同形的 `{ text: 原文, intents, confidence }`。
- 只有一句时，结果必须与 `parse(text, ctx)` 完全一致（向后兼容）。
- `confidence`：取各句里最低的（`none` < `low` < `medium` < `high`）；某一句没有解析出任何意图时，整体至多为 `low`；全部都没有意图时为 `none`。
- `/api/parse` 改为调用 `parseMulti`；200 字的长度限制不变。键盘打字时也会跟着受益。
- 超过 5 句时不能悄悄丢掉：`parseMulti` 的返回里额外加一个可选字段 `truncated: true`（只在被截断时出现，其余字段与 `parse()` 同形），`/api/parse` 原样透传；前端据此在确认卡上方提示「只处理了前 5 句，后面的没有录入，请分开说。」
- 兼容性：现有 `test/parse.test.js` 里没有任何一句话在句内使用「。！!？?；;」，所以现有用例不受影响；新增一个测试，对现有用例里的每一句断言 `parseMulti(句子, ctx)` 与 `parse(句子, ctx)` 的结果完全一致。

### 前端

- 一句话录入表单里，相机按钮旁加麦克风按钮（新增 `i-mic` 图标）。仅当 `GET /api/asr/status` 返回已启用，且 `window.isSecureContext` 为真、`navigator.mediaDevices.getUserMedia` 存在时才显示，否则隐藏。
- 点一下开始录音（第一次浏览器会请求麦克风权限）：按钮变成录音状态（红色，显示已录秒数，提示「再点一下结束」）；再点一下结束；到 `maxSeconds` 秒自动结束。拒绝权限或没有麦克风：toast 给出中文提示（如「没有麦克风权限，请在浏览器设置里允许」），按钮恢复。
- 如果浏览器解码不了录下来的音频（例如个别旧版 iOS Safari），toast「这个浏览器暂时不支持语音录入」，按钮恢复；第一版不做退回到 `AudioWorklet` 的备用方案。
- 语音文字到达时，输入框里原有的内容被**替换**（不追加），然后自动解析。
- 结束后：显示「识别中…」并禁用按钮；把录音转成 16kHz 单声道 16 位 WAV；`POST /api/asr/transcribe`；成功后把 `text` 填进 `#quick-text` 并自动执行与点「录入」相同的解析流程，弹出确认卡；`text` 为空 → toast「没听清，再说一遍试试」。任何失败都 toast 服务器返回的中文消息，并保证按钮恢复、没有残留的「识别中」状态。
- WAV 编码与重采样放进一个纯函数模块（浏览器里 `window.WavEnc`，Node 里可 `require`），可用 Node 断言测试：输入 `Float32Array` 采样和采样率，输出 16kHz 单声道 16 位 PCM 的 WAV 字节（含正确的 RIFF/WAVE/fmt/data 头）；采样值需限幅到 [-1, 1]。
- 把现有「录入」表单提交处理抽成一个可重复调用的函数，让文字输入和语音识别共用。

### 文档与验收

- `README.md` 功能表加一行「语音录入」；`DEPLOY.md` 加配置小节；`验收清单.md` 追加未勾选的验收项（含：只在 HTTPS 且已配置时出现、拒绝权限的提示、一口气说两件事得到两条意图、识别失败有提示且按钮恢复、次数用完提示等）。

## 交给构建者决定

- 提示词的具体措辞；麦克风按钮的位置和样式、录音状态的视觉；各处 toast 文案（含义要与上面一致）。
- 浏览器端怎么得到采样数据：推荐 `MediaRecorder` 录音，再用 `AudioContext.decodeAudioData` 解码并用 `OfflineAudioContext` 重采样到 16kHz，这样不同浏览器（安卓 Chrome 的 WebM、iPhone Safari 的 AAC）都能处理；也可以用 `AudioWorklet`。
- 小票识别和语音识别共用的防护逻辑（边读边限的响应读取、超时毫秒换算、用量计数与持久化、进行中标志、重复的错误映射）：可以抽成共享模块，让两个服务都使用，前提是小票识别现有的 54 项测试保持通过；也可以先各自实现再抽取，请避免大段原样复制。
- 测试的组织方式。建议：`lib/asr.js` 与服务用 Node 断言离线测试；`parseMulti` 的用例加进 `test/parse.test.js`；WAV 编码器单独一个测试文件。

## 我替用户做的决定（请核对）

1. 每天默认 100 次（比小票多，因为很便宜）、识别超时 30 秒、录音最长 30 秒、请求体最大 2 MB、最多拆 5 句，都是我定的默认值，除录音时长外都可配置。
2. 两个汉字之间的空白当作句子分隔，是因为实测识别结果在两句话之间用的是空格；数字或字母旁边的空白不动。
3. 识别后自动解析并弹出确认卡（用户确认前不会改库存），不是只把文字填进输入框等用户再点。
4. `parseMulti` 同时让键盘输入也支持用句号隔开的多件事（这改变了 `/api/parse` 的行为，用户已同意）。
5. 麦克风按钮只在 HTTPS 页面且已配置时显示，不做降级方案（比如退回到键盘语音）。
6. 第一版只支持 `responses` 格式；`format` 字段保留，以后扩展。
7. 录音最长秒数做成配置项 `maxSeconds`（默认 30）并通过状态接口告诉前端：已验证的只是 136KB 的短录音，30 秒的 WAV 约 960KB（转成 base64 约 1.3MB）能否被识别服务接受还没验证；如果被拒绝，管理员调小这个值即可，不用改代码。验收时需要用真机录一段接近最长时长的语音。
8. 超过 5 句不是悄悄丢掉，而是提示用户（`truncated` 字段）。
9. 输入框里已有内容时，语音文字是替换而不是追加。
10. 个别浏览器解码不了录音时只提示不支持，第一版不做 `AudioWorklet` 备用方案；iPhone Safari 和安卓 Chrome 的真机验证由用户完成。
11. 日期、计数、防护规则与小票识别一致（服务器本地日期，失败也计数），但语音和小票各自独立，互不阻塞。
