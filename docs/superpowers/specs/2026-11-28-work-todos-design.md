# 每周工作：待办单独成清单、每天可直接添加删除 设计（改动）

日期：2026-11-28　状态：待用户确认
前置：`2026-11-27-work-log-design.md`（本次在它的基础上修改，未提及的地方保持原样）

## 意图与原因

用户使用「每周工作」后提出两点：

1. **待办项移出来**：待办不该混在每天的记录里。待办可以选日期，也可以不选（默认不选），并且能**单独查询哪些还没做**。
2. **每天可以单独添加、删除**：现在要先点某天的标题改「记到哪天」再用顶部输入框，删除要先点开编辑，太绕。希望每天自己就有添加和删除。

用户在周报上做了选择：**「下周计划」带上全部没做完的待办**（含没选日期的、已过期的）。

## 目标

- 「每周工作」页分两个标签：**记录**（原来的周视图，只放「已做」）和**待办**（单独清单）。
- 待办：文字 + 可选日期；可勾选完成；可编辑、删除；有「还没做 / 已完成 / 全部」三个视图，**默认「还没做」**。
- 记录页每一天的标题上有自己的「＋」：点开该天的输入行直接记；每条记录自己有删除，一点即删，带「撤销」。
- 周报按新规则生成：「做了什么」= 本周的记录 + 本周完成的待办（按完成那天）；「下周计划」= 全部没做完的待办。
- 已有的待办自动迁移，不丢。

## 非目标 / 反目标

- 不做：待办的语音录入、优先级、重复待办、提醒通知、「还没做」数量角标、手动修改完成日期、待办子任务。
- 不改：人员（添加、改名、切换）、顶部输入框对「记到哪天」的行为、语音录入（仍只记「已做」）、周报是纯规则文字、不自动清理。
- 反目标：升级后旧待办丢失或变成「已做」记录；取消勾选后周报里还留着；撤销删除后数据对不上；旧页面（浏览器缓存）还在用旧接口时悄悄写错数据。

## 约束

- 零第三方依赖；沿用现有结构（`lib/work.js` 纯逻辑 + 离线测试、`server.js` 接口、`public/` 界面）。
- 旧库升级靠启动时迁移，迁移要在一个事务里、重复启动不会再改动、不依赖手动步骤。
- 日期一律 `YYYY-MM-DD`；「今天」前端用浏览器本地日期（与现有一致）。
- 不启动测试服务器或浏览器；冒烟测试只写不跑；前端靠 `node --check`。

## 已考虑的做法

- **A. 待办单独一张表（已选）**：待办有自己的字段（可空的日期、完成日期），记录表只剩「已做」。语义清楚，查询「还没做」简单，周报逻辑也直白。代价是要迁移旧数据、接口多一组。
- B. 仍放在原记录表，日期改成可空：改动小，但「记录」和「待办」两种东西共用一套字段和接口，每天的周视图要到处过滤待办，容易混。不选。

## 已定的设计

### 数据

新表 `work_todos`：

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `person_id` | → `work_people`，级联删除 |
| `text` | 去首尾空白后非空、最长 200 字 |
| `due_date` | 待办日期，**空串表示没选日期**；非空时必须是真实的 `YYYY-MM-DD` |
| `done` | 0 / 1 |
| `done_date` | 完成日期，未完成时为空串；勾选时由前端传浏览器本地「今天」，缺省用服务器本地日期 |
| `created_at` | 创建时间 |

索引：`work_todos(person_id, done)`。`work_entries` 表保留，**不再有待办**（`kind` 列保留但只会是 `done`，`done` 列不再使用）。

**迁移**（启动时，一个事务，可重复执行）：把 `work_entries` 里 `kind = 'todo'` 的行搬进 `work_todos`：原 `date` → `due_date`；原 `done` 保持；已完成的 `done_date` = 原 `date`；`created_at` 保持；然后从 `work_entries` 删掉这些行。执行后库里不再有 `kind='todo'` 的记录，所以重复启动什么都不会再改动。

### 接口（均需登录，错误统一 `{error}`）

**记录（`work_entries`）**——变化：

| 接口 | 变化 |
|---|---|
| `GET /api/work/week` | 每条记录只返回 `{id, date, text}`（不再有 `kind` / `done`） |
| `POST /api/work/entries`、`POST /api/work/entries/batch`、`PUT /api/work/entries/:id` | `kind` 可以不传（默认 `done`）；传了就必须是 `done`，否则 400「类型无效」——这样旧页面误传 `todo` 时会得到明确的错误，而不是悄悄写成记录。`done` 字段不再接受（忽略） |
| 其余（删除、批量删除） | 不变 |

**待办（新）**：

| 接口 | 说明 |
|---|---|
| `GET /api/work/todos?person=<id>&filter=open\|done\|all` | `person` 必填（缺失或无效 400「人员不存在」）；`filter` 默认 `open`，非法 400「filter 无效」。返回 `[{id, text, due_date, done, done_date}]`。`open`：有日期的按日期升序（同日按 id），没日期的排在后面（按 id）；`done`：按完成日期倒序，**最多 200 条**；`all`：先 `open` 的全部，再 `done` 的最近 200 条 |
| `POST /api/work/todos` `{person_id, text, due_date?, done?, done_date?}` | 新建。`due_date` 不传或空串 = 没选日期。`done` / `done_date` 仅用于「撤销删除」时原样恢复：`done` 为 true 时 `done_date` 缺省取服务器本地日期；`done` 为 false 时 `done_date` 强制为空 |
| `PUT /api/work/todos/:id` `{text?, due_date?, done?, done_date?}` | 局部修改，给了的字段才改。`due_date` 传空串清除日期。`done` 必须是布尔值（否则 400「done 应为 true 或 false」）；`done` 变 true 且没给 `done_date` 时取服务器本地日期；`done` 变 false 时 `done_date` 清空。不存在 404「待办不存在」 |
| `DELETE /api/work/todos/:id` | 删除；不存在 404「待办不存在」 |
| `GET /api/work/report?start=&person=` | 接口不变，内容按下面的新规则 |

### 周报（`lib/work.js` 的 `buildReport`）

签名改为 `buildReport({ start, entries, doneTodos, openTodos })`：

- `entries`：本周的记录 `[{date, text}]`（按 id 顺序）；`doneTodos`：**本周完成**的待办 `[{date, text}]`，`date` 取 `done_date`（按 id 顺序）；`openTodos`：全部没完成的待办 `[{due_date, text}]`。
- 「做了什么」按周一到周日列出；同一天内先列记录，再列完成的待办。
- 「下周计划」= `openTodos`：有日期的按日期升序（同日保持输入顺序），没日期的排在最后。
- **本周没有任何「做了什么」（`entries` 和 `doneTodos` 都为空）时不生成周报**（`{text:'', empty:true}`），即使有没完成的待办。
- 文字格式不变（标题 `本周工作（11/23 – 11/29）`、星期名、`- ` 前缀、`下周计划` 一节）。

### 界面

```
每周工作                         [人员]
[ 记录 | 待办 ]
```

**记录标签**（原周视图）：

```
‹ 11月23日 – 11月29日 ›  [本周]
记到：11月27日 周五
[ 今天做了什么…  ] [🎤] [记]        ← 顶部输入框保留，去掉「已做 / 待办」开关
周二 11/24                    [＋]
  · 修了登录 bug                 ×
  [ 在这一天再记一条…      ] [记]    ← 点 ＋ 展开
[生成周报]
```

- 每一天的标题行右侧有「＋」：点开该天的输入行，回车或点「记」记到**这一天**（不改顶部的「记到」），记完保持展开、清空并聚焦，方便连续记；再点「＋」收起；同一时间只展开一天。
- 每条记录右侧有「×」：点一下立即删除，弹出「已删除」+「撤销」（约 7 秒）；撤销 = 用原来的日期和文字重新创建（会排在当天末尾）。点记录文字仍打开编辑弹层（文字、日期，**去掉「类型」**，保留「删除」）。
- 顶部输入框和语音仍记到「记到：…」那一天，**只记「已做」**。

**待办标签**：

```
待办   [还没做 | 已完成 | 全部]
[ 添加待办…        ] [日期（可不选）] [添加]
☐ 联系供应商        没选日期            ×
☐ 写方案            11/20 已过期  [挪到下周]  ×
☑ 整理测试报告      完成于 11/25        ×
```

- 默认「还没做」。添加：文字必填，日期可不选；添加后清空文字和日期并聚焦。
- 圆圈勾选完成（完成日期取今天），再点取消。完成的行变淡带删除线，显示「完成于 M/D」。
- 「已过期」= 没完成、有日期且日期早于今天，用橙色提示。
- 「挪到下周」只出现在**没完成且有日期**的待办上：日期改为「原日期和今天中较晚的那天」所在周的**下一周周一**。
- 每行有「×」，一点即删并带「撤销」（撤销时把原来的文字、日期、完成状态原样恢复）。点待办文字打开编辑弹层：文字、日期（带「清除日期」按钮）、删除。
- 切换人员时，两个标签都只显示这个人的；翻周和「生成周报」只在「记录」标签里。
- 待办标签里没有语音按钮。

### 兼容

- 前端文件是 `no-cache`，刷新后就是新页面。万一旧页面还开着，它对 `POST /api/work/entries` 传 `kind: 'todo'` 会得到 400「类型无效」，不会误写；它读到的周视图里不再有待办，属于预期。

### 测试

- `test/work.test.js`：更新 `buildReport` 的用例——完成的待办按完成日期列入「做了什么」、同一天先记录后待办；下周计划含没日期的（排在最后）和已过期的、有日期的按日期升序；本周没有任何已做时为空；仍覆盖跨月、跨年。`splitSpoken`、`nextMonday` 不变。
- `test/smoke.js`：把每周工作块里依赖旧待办的部分改成新接口，并补：待办新建（有日期 / 没日期）、`filter` 三种视图与排序、`filter` 非法 400、勾选记录完成日期、取消勾选清空、改日期 / 清除日期、`person` 缺失或非法 400、人员隔离、撤销式重建（`done` + `done_date` 原样恢复）、周报中的完成待办和下周计划；记录接口传 `kind: 'todo'` 得 400。只写不跑。
- **迁移**要有一条覆盖：用旧结构的数据验证迁移结果（旧待办 → 新表，日期和完成状态对得上，旧表里不再有 `todo`，重复执行不变）。因为不启动服务，做成可在内存数据库上直接运行的离线测试（把迁移写成可单独调用的函数）。

## 交给构建者决定

- 标签、行内输入、已过期提示的具体样式；两个新标签在手机窄屏下的排版。
- 迁移函数的具体写法，只要满足「一个事务、可重复、旧表不再有 todo、可离线测试」。
- 待办列表的 `all` 视图里「还没做」和「已完成」之间是否加一条分隔小标题。

## 我替用户做的决定（请核对）

1. 顶部输入框和语音只记「已做」，待办在「待办」标签里添加（待办不做语音）。
2. 记录的删除不再弹确认框，改成「已删除 + 撤销」；撤销后会排在当天末尾。
3. 旧待办自动迁移：原日期变成待办日期；已完成的，完成日期取原日期。
4. 完成待办记下完成日期，周报按完成那天列入「做了什么」；取消勾选后从周报消失。
5. 「挪到下周」只给有日期的未完成待办，改到「原日期和今天中较晚者」的下一周周一。
6. 「下周计划」= 全部没做完的待办（用户选的 A）；有日期的在前、没日期的在后。
7. 本周一条「做了什么」都没有时仍不生成周报，即使有没完成的待办。
8. 「已完成」视图最多显示最近 200 条。
9. 记录的编辑弹层去掉「类型」。
