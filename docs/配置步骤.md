## 0. 先选部署方式

| | 方式一 Windows 本机 | 方式二 Linux 小主机 | 方式三 云服务器 |
|---|---|---|---|
| 适合 | 先试一试、家里一台常开的电脑 | 常年开机的树莓派 / 开发板 / NAS | 想在外面也能用、要用语音录入 |
| 访问范围 | 同一 WiFi | 同一 WiFi（外网可用 Tailscale） | 任何网络 |
| HTTPS | 没有 | 没有（可自行加） | 有域名即可配 |
| 能用语音录入 | 否（需 HTTPS） | 否（需 HTTPS） | 是 |
| 花费 | 无 | 设备一次性 | 服务器 + 域名按年 |

**小票录入**不需要 HTTPS，三种方式都能用；**语音录入**需要 HTTPS（浏览器的限制），所以需要方式三，或者自己给方式二加一层 HTTPS 反向代理。

## 1. 环境要求

- **Node.js**：建议 **22.13 或更新**（本项目开发和测试用的是 Node 24）。项目用 Node 自带的 SQLite（`node:sqlite`），不需要安装任何 npm 包，也不需要 `npm install`。`package.json` 声明的最低版本是 22.5，但更早的 22.x 里 SQLite 需要额外的启动参数，所以以 22.13+ 为准。
- 检查版本：`node --version`。
- 不需要数据库服务、Docker 或构建工具。
- 手机浏览器：iPhone 用 Safari，Android 用 Chrome。

---

## 2. 方式一：Windows 电脑本机运行

1. 安装 Node.js（官网下载 LTS 版本，安装时保持默认选项）。
2. 把项目文件夹放到电脑上（例如 `D:\home-inventory`）。
3. 双击 `start.bat`。第一次运行，终端会打印：

   ```
   首次启动：已生成 …\data\config.json，初始密码为 "home1234"，登录后可在「设置」中修改。
   家庭物资清点表已启动：
     本机：   http://localhost:3000
     手机访问：http://192.168.1.150:3000  （需与本机在同一 WiFi）
   ```
4. 电脑上打开 `http://localhost:3000`；手机连同一个 WiFi，打开终端里打印的「手机访问」地址。
5. 手机浏览器里选「添加到主屏幕」，以后像 App 一样打开。
6. 手机连不上：Windows 防火墙弹窗时选「允许」；没弹窗的话，在「Windows 安全中心 → 防火墙 → 允许应用通过防火墙」里放行 `node.exe`。

**开机自启**（可选）：`Win + R` 输入 `shell:startup`，把 `start.bat` 的快捷方式放进去。关闭终端窗口就是停止服务。

**改端口或初始密码**：编辑 `start.bat`，在 `node` 那一行前面加：

```bat
set PORT=8080
set INVENTORY_PASSWORD=你的初始密码
```

初始密码只在**第一次生成 `config.json` 时**生效，之后改密码要在网页「设置」里改。

## 3. 方式二：Linux 开发板 / NAS / 家里的小主机

适用于 Debian / Ubuntu / Armbian / Raspberry Pi OS 等。

1. 把源码推到你自己的 Git 仓库（GitHub / Gitee / 自建 Gitea 均可），在设备上克隆：

   ```bash
   cd ~
   git clone https://github.com/<你的用户名>/home-inventory.git
   cd home-inventory
   ```
2. 一键安装为系统服务：

   ```bash
   sudo bash deploy/install.sh
   ```

   脚本会：检查并按需安装 Node.js；创建 `data/` 目录；用 `deploy/home-inventory.service` 模板生成 systemd 服务（自动填入用户名、目录、node 路径），设为开机自启并立即启动；如果启用了 ufw 防火墙，放行 3000 端口；打印手机访问地址。
3. 验证：

   ```bash
   systemctl status home-inventory         # 应该是 Active: active (running)
   curl -s http://localhost:3000/api/me    # 应该返回 {"authed":false}
   ```
4. 手机连同一 WiFi，打开 `http://<设备IP>:3000`，初始密码 `home1234`，**登录后立刻改掉**。

**常用命令**

```bash
journalctl -u home-inventory -f            # 实时日志
sudo systemctl restart home-inventory      # 重启
```

**修改端口、数据目录等**：编辑 `/etc/systemd/system/home-inventory.service` 里的 `Environment=` 行，然后：

```bash
sudo systemctl daemon-reload && sudo systemctl restart home-inventory
```

> 如果把数据目录（`INVENTORY_DATA`）改到别处，要同步修改 service 里的 `ReadWritePaths=`，否则服务没有写权限。

**外出时也想访问**：服务本身是 HTTP 明文、单一密码，**不要把端口直接映射到公网**。推荐 Tailscale（设备和手机都装，登录同一账号，手机在任何网络下用设备的 Tailscale 地址访问）；或者用方式三的云服务器。

## 4. 方式三：云服务器 + 域名 + HTTPS

这是用语音录入的推荐方式。以下以阿里云 Ubuntu 20.04 / 22.04 为例，其他云厂商类似。

### 4.1 准备

- 一台云服务器（1 核 1G 起，推荐 1 核 2G），Ubuntu 20.04 / 22.04。
- 一个域名（用于 HTTPS），例如 `home.example.com`。
- 在云厂商控制台的**安全组**里放行 22、80、443 端口。

### 4.2 一键部署

```bash
ssh root@你的公网IP
git clone <你的仓库地址>      # 例如 https://gitee.com/<你的用户名>/home_restore.git
cd home_restore/deploy
sudo bash cloud-install.sh
```

脚本会询问：

- **是否配置域名？** 输入 `y` 并填域名；直接回车则用 IP 访问（HTTP）。
- **初始密码？** 留空默认 `home1234`。
- **内部端口？** 留空默认 `3000`。

它会自动：安装 Node.js 22、Nginx、certbot、ufw；把应用下载到 `/opt/home-inventory`；创建并启动 systemd 服务；配置 Nginx 反向代理（含登录接口的限流）；放行防火墙端口。

### 4.3 配置 HTTPS

1. 到域名服务商添加一条 A 记录：`home`（或你想用的前缀）→ 你的公网 IP。
2. 等 DNS 生效（1–10 分钟），用 `nslookup home.example.com` 检查。
3. 在服务器上申请证书（脚本里选了域名时可能已经帮你做了）：

   ```bash
   sudo certbot --nginx -d home.example.com -m 你的邮箱 --agree-tos --non-interactive
   ```
4. 手机访问 `https://home.example.com`，地址栏要有锁图标、没有证书警告。

### 4.4 自己配 Nginx 时要注意

- 反向代理到应用的内部端口（默认 `3000`）。
- **请求体大小要放宽**：Nginx 默认只允许 1MB，而物品图片最大 15MB、户型图纸最大 20MB、小票图片最大 8MB、语音录音最大 2MB。请设置 `client_max_body_size 20M;`（部署脚本里已经设了）。
- 转发 `X-Forwarded-Proto` 等常见头（部署脚本里已配）。

### 4.5 云服务器上的日常管理

```bash
sudo systemctl status home-inventory       # 状态
sudo systemctl restart home-inventory      # 重启
sudo journalctl -u home-inventory -n 50 --no-pager   # 最近日志
```

## 5. 首次登录与改密码

1. 打开网址，输入初始密码 `home1234`（或你在部署时设的）。
2. 进入底部「设置」→ 修改密码（新密码至少 4 位）。**改完后所有设备都需要重新登录。**
3. 登录状态在每台设备上保留 180 天。

**忘了密码**：停掉服务，删除 `data/config.json`，重新启动，会用 `INVENTORY_PASSWORD`（没设就是 `home1234`）重新生成。注意这样会同时清掉小票识别和语音识别的配置，需要重新填。

## 6. 配置项总表

### 6.1 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `3000` | 监听端口 |
| `INVENTORY_DATA` | `<项目>/data` | 数据目录（数据库、图片、`config.json`） |
| `INVENTORY_PASSWORD` | `home1234` | 仅第一次生成 `config.json` 时生效 |
| `NODE_OPTIONS` | 部署模板里有 `--max-old-space-size=…` | 内存小的设备限制 Node 堆大小 |
| `RECEIPT_API_URL` / `RECEIPT_API_KEY` / `RECEIPT_MODEL` / `RECEIPT_FORMAT` / `RECEIPT_EXTRA` / `RECEIPT_TIMEOUT_S` / `RECEIPT_DAILY_LIMIT` | 见第 7 节 | 小票识别 |
| `ASR_API_URL` / `ASR_API_KEY` / `ASR_MODEL` / `ASR_FORMAT` / `ASR_EXTRA` / `ASR_TIMEOUT_S` / `ASR_DAILY_LIMIT` / `ASR_MAX_SECONDS` | 见第 8 节 | 语音识别 |

### 6.2 `data/config.json`

首次启动自动生成，内容大致是：

```json
{
  "passwordHash": "…（自动生成，不要改）…",
  "secret": "…（自动生成，不要改）…",
  "receipt": { "…": "可选，小票识别，见第 7 节" },
  "asr": { "…": "可选，语音识别，见第 8 节" }
}
```

- `passwordHash` 和 `secret` 是自动生成的，**不要手动改**，改了会导致所有设备登录失效。
- 手动编辑时，`receipt` 和 `asr` 与它们**并列写在最外层的 `{}` 里面**；前一项末尾要补英文逗号，最后一项后面不要逗号；引号一律用英文半角的 `"`。
- 写错了，服务启动时会提示「config.json 不是合法的 JSON，请检查括号、逗号和引号」并退出，不会把内容打印到日志里。
- 改完设置权限并重启：`chmod 600 data/config.json`，再重启服务。
- 环境变量优先于 `config.json`，按项逐个覆盖。环境变量的值**不会**写回 `config.json`。

### 6.3 放 key 的位置

识别服务的 key 是敏感信息：

- **推荐写在 `data/config.json` 里**，并 `chmod 600`。
- **不要写进 systemd 单元文件的 `Environment=`**：单元文件和 `systemctl show` 通常所有用户都能读。
- 想用环境变量的话，放进只有 root 能读的环境变量文件：

  ```bash
  sudo install -m 600 -o root -g root /dev/null /etc/home-inventory.env
  sudoedit /etc/home-inventory.env        # 每行一项，如 RECEIPT_API_KEY=你的key
  # 再在单元文件的 [Service] 段加一行：EnvironmentFile=-/etc/home-inventory.env
  sudo systemctl daemon-reload && sudo systemctl restart home-inventory
  ```
- 建议给每个功能**单独申请一个 key**，余额放少一点，必要时能设额度上限。
- key 不要发给别人，也不要贴到聊天或截图里。贴终端输出前先看一眼有没有 key。

## 7. 配置小票识别（可选）

### 7.1 你需要准备

一个**能读图的多模态模型**的接口：

- 接口地址（完整的，写到最后的路径）
- key
- 模型名
- 接口格式（见下表）

| `format` | 适用 | 地址示例 |
|---|---|---|
| `openai`（默认） | OpenAI 兼容接口（DeepSeek 官方、多数中转站和国内模型） | `https://…/chat/completions` |
| `anthropic` | Anthropic 格式 | `https://…/v1/messages` |
| `responses` | 火山方舟的 Responses 接口 | `https://ark.cn-beijing.volces.com/api/v3/responses` |

具体的地址和模型名以你所用服务商的官方文档为准。

### 7.2 写配置

编辑 `data/config.json`，加一个 `receipt` 对象：

```json
"receipt": {
  "url": "https://api.deepseek.com/chat/completions",
  "key": "你的 key",
  "model": "模型名",
  "format": "openai",
  "extra": {},
  "timeoutSec": 60,
  "dailyLimit": 30
}
```

火山方舟（Responses 格式）的例子，需要关闭模型的「深度思考」，否则会很慢、很费 token：

```json
"receipt": {
  "url": "https://ark.cn-beijing.volces.com/api/v3/responses",
  "key": "你的 key",
  "model": "能读图的模型名",
  "format": "responses",
  "extra": { "thinking": { "type": "disabled" } }
}
```

| 字段 | 说明 |
|---|---|
| `url`、`key`、`model` | 三项齐全才算已配置 |
| `format` | `openai` / `anthropic` / `responses` |
| `extra` | JSON 对象，合并进请求体最外层；用来关闭思考、限制输出长度（参数名因服务商而异：`max_tokens`、`max_completion_tokens`、`max_output_tokens`） |
| `timeoutSec` | 超时秒数，默认 60 |
| `dailyLimit` | 每天最多识别几次，默认 30，`0` 表示不限（防止误操作烧钱） |

### 7.3 重启并确认

```bash
sudo chmod 600 data/config.json
sudo systemctl restart home-inventory
sudo journalctl -u home-inventory -n 20 --no-pager
```

日志里应该有「小票识别已启用（模型 …）」。如果是「小票识别配置有问题：…」，按提示改。

### 7.4 在手机上验证

刷新页面（旧页面缓存没更新的话，强制刷新或重开「主屏幕」图标），物品页的输入框旁出现相机按钮。拍一张小票，应该弹出确认卡：库存里已有的显示「补货」，没有的显示「新增」。

识别服务的**用量**记在 `data/receipt-usage.json`，全家共用，重启不会清零。

## 8. 配置语音识别（可选）

### 8.1 前提

1. **页面必须是 HTTPS**（见第 4 节）。否则浏览器不允许录音，按钮不会出现。
2. 一个**能听音频的模型**的接口。第一版只支持火山方舟的 Responses 接口（音频通过 `input_audio` 传）。方舟的大模型和火山引擎的专门语音识别产品是两个不同的产品，key 也不一样；这里要的是**大模型**的接口，并且该模型支持音频输入（在模型详情页的输入类型里能看到「音频」）。
3. 语音识别和小票识别是**两套完全独立**的配置，次数也各算各的，互不影响。

### 8.2 写配置

在 `data/config.json` 里加一个 `asr` 对象（与 `receipt` 并列）：

```json
"asr": {
  "url": "https://ark.cn-beijing.volces.com/api/v3/responses",
  "key": "你的 key",
  "model": "能听音频的模型名",
  "format": "responses",
  "extra": { "thinking": { "type": "disabled" } },
  "timeoutSec": 30,
  "dailyLimit": 100,
  "maxSeconds": 30
}
```

| 字段 | 说明 |
|---|---|
| `url`、`key`、`model` | 三项齐全才算已配置 |
| `format` | 目前只支持 `responses` |
| `extra` | 同小票识别；方舟的模型建议关闭思考 |
| `timeoutSec` | 超时秒数，默认 30 |
| `dailyLimit` | 每天最多识别几次，默认 100，`0` 表示不限 |
| `maxSeconds` | 单段录音最长秒数，默认 30，**最大 60**。识别服务如果拒绝较长的录音，调小它即可 |

### 8.3 重启并确认

```bash
sudo chmod 600 data/config.json
sudo systemctl restart home-inventory
sudo journalctl -u home-inventory -n 20 --no-pager
```

日志里应该有「语音识别已启用（模型 …）」。

### 8.4 在手机上验证

1. 用 **HTTPS** 地址打开页面（地址栏有锁）。物品页的输入框旁出现麦克风按钮。
2. 第一次点击，浏览器会请求麦克风权限，选「允许」。
3. 点一下开始（按钮变红并显示秒数），说一句「买了两盒酸奶放冷藏」，再点一下结束。
4. 出现「识别中」，然后弹出确认卡。
5. 再试一口气说两件事：「把鸡蛋放入冰箱冷藏，买了五花肉一盒」，应该得到两条。
6. **iPhone Safari 和安卓 Chrome 都试一遍**：不同浏览器录出来的音频格式不一样，个别浏览器可能解码失败，会提示「这个浏览器暂时不支持语音录入」。
7. 用真机录一段接近最长时长的话，确认识别服务接受这么长的录音；不接受就调小 `maxSeconds`。

录音在浏览器里转成 16kHz 单声道 WAV 再上传（最大 2MB），**只发给你配置的识别服务，不会保存**。用量记在 `data/asr-usage.json`。

## 9. 备份与恢复

所有数据都在 `data/` 目录。

**手动备份**：停掉服务（或在没人用的时候），整个复制 `data/` 目录。

**自动备份（Linux）**：每天 3 点，保留最近 14 份，默认放到 `~/inventory-backups`：

```bash
sudo apt-get install -y sqlite3          # 可选：有它备份时会用 SQLite 在线备份保证一致性
chmod +x deploy/backup.sh
( crontab -l 2>/dev/null; echo "0 3 * * * $HOME/home-inventory/deploy/backup.sh $HOME/inventory-backups" ) | crontab -
```

备份目录可以指到 U 盘或 NAS 的挂载点。

**恢复**：停服务 → 用备份覆盖 `data/` → 启动服务。

**只想要物品清单**：在网页「设置」里导出 CSV（不含图片）。

> `data/config.json` 里有密码哈希、会话密钥和识别服务的 key，备份文件要妥善保管。

## 10. 更新升级

```bash
cd /opt/home-inventory          # 或你的项目目录
sudo tar -czf ~/backup-before-update-$(date +%F).tar.gz data/    # 先备份
sudo git pull
sudo systemctl restart home-inventory
sudo journalctl -u home-inventory -n 20 --no-pager
```

- 数据库结构会在启动时**自动升级**（只加表、加列，不会删数据），不需要手动迁移。
- 更新后手机上**强制刷新**页面，或把「主屏幕」图标关掉重新打开，避免用到旧的网页缓存。
- `git pull` 提示有本地改动会覆盖时，先看一下改了什么（`git status`、`git diff`），不要直接丢弃。
- Windows 本机：用新文件覆盖项目文件夹里的代码（**不要覆盖 `data/` 目录**），重新双击 `start.bat`。

## 12. 常见问题

| 现象 | 处理 |
|---|---|
| `Cannot find module 'node:sqlite'` 或版本提示 | Node 太旧，升级到 22.13 或更新；`which node` 确认 systemd 用的是新装的那个 |
| `EADDRINUSE` | 端口被占用：`sudo ss -ltnp | grep 3000`，换 `PORT` 或停掉占用进程 |
| 手机打不开，服务器本机 `curl` 正常 | 防火墙 / 云安全组没放行端口；手机和设备不在同一网段（访客 WiFi 常常互相隔离） |
| `EACCES` / 数据库只读 | `sudo chown -R <用户>:<用户> data`；改过 `INVENTORY_DATA` 的话，确认 service 里 `ReadWritePaths=` 也改了 |
| 上传图片失败 413 | 单张物品图上限 15MB、图纸 20MB、小票图 8MB；经过 Nginx 时检查 `client_max_body_size`（浏览器端会先压缩，一般不会触发） |
| 看不到相机按钮 | 没配置小票识别，或日志里有「小票识别配置有问题」；改完配置要重启服务并刷新页面 |
| 看不到麦克风按钮 | 没配置语音识别；页面不是 HTTPS；或浏览器不支持录音 |
| 启动提示「config.json 不是合法的 JSON」 | 配置文件里有语法错误，常见原因：漏了逗号、用了中文引号 “ ”；恢复备份或改正后重启 |
| 识别提示「识别服务拒绝了请求，请检查服务器上的 key」 | key 不对、过期、没有开通该模型，或余额不足 |
| 识别提示「连不上识别服务」 | 服务器访问不了该服务（网络、地址写错）；国内服务器连境外服务常常不通 |
| 识别提示「今天的识别次数用完了」 | 达到 `dailyLimit`，第二天自动恢复；也可以调大它 |
| 识别很慢（几十秒） | 模型开着「深度思考」，在 `extra` 里关闭（方舟：`{"thinking":{"type":"disabled"}}`），或换成不带思考的型号 |
| 板子重启后服务没起来 | `systemctl is-enabled home-inventory` 应为 `enabled`；`journalctl -u home-inventory -b` 看启动日志 |

更多云服务器相关的问题（证书申请失败、内存不足等）见 [deploy/CLOUD.md](../deploy/CLOUD.md)。
