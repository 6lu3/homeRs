# 拍小票 / 订单截图录入库存 设计

日期：2026-11-24　状态：设计已向用户讲解并认可，待用户审阅本文档

## 意图与原因

家里买菜、买日用品后，要把买的东西一件件录进库存很麻烦。用户希望拍一张购物小票（或截一张 App 订单图），由多模态大模型读出商品和数量，弹出确认卡，核对后一键入库。

用户已用真实小票实测过两个服务，效果可用：DeepSeek 官方接口（openai 兼容格式）约 2.4 秒，火山方舟（responses 格式，需关闭思考）约 3 秒。用户之后还会换成更好的模型，所以接口地址、key、模型名、接口格式、额外参数都必须是可配置的。

使用者：全家人，主要在手机上用。

## 目标

- 物品页有一个相机按钮：拍照或从相册选图 → 识别 → 弹出现有的确认卡 → 确认后写入库存。
- 识别结果复用一句话录入的「录入意图」格式，库存里有的物品「补货」（加数量），没有的「新增」。
- 识别服务完全由服务器配置决定（地址、key、模型名、接口格式、额外参数），换模型只改配置。
- 支持三种接口格式：`openai`（chat/completions）、`anthropic`（messages）、`responses`（方舟 Responses 接口）。
- 防烧钱、防重复、防泄露（见约束）。

## 非目标 / 反目标

- 不做 PDF 电子发票（请用户截图）；不做一次多张图。
- 不保存小票图片到服务器；不做花费统计、不记录价格。
- 不使用小票上的日期（实测同一张小票三次读出三个不同年份）；不识别位置和到期日。
- 不做网页上的设置页（站点是 http，在网页里填 key 会明文传输）。
- 不把库存名单发给模型。
- 反目标（即使功能看起来能用也算失败）：未经确认卡就改动库存；key 出现在任何接口响应、日志或前端；识别服务出问题时拖垮其他功能；无上限地花钱。

## 约束

- 零第三方依赖；Node ≥ 22.5；用 Node 自带的 `fetch` 调用识别服务。
- 沿用现有风格与结构：`lib/` 放纯逻辑，`server.js` 放接口，`public/app.js` 放前端，测试放 `test/`。
- 所有新接口走现有登录检查。
- 图片只在内存中转发，不写磁盘。
- key 只存在于服务器配置（`data/config.json` 或环境变量）；不通过任何接口返回，不写日志，错误信息里也不能带。
- 界面文字全部用中文。所有来自识别结果或用户的文字渲染时必须用现有的 `esc()`。

## 已考虑的做法

识别结果怎么变成录入意图：
- **A. 模型返回结构化商品列表，服务器在本地用现有规则匹配库存（已选）**：便宜，不泄露库存。
- B. 把库存里的物品名一起发给模型，让它选出对应项：匹配更准，但更费 token，且把库存名单交给第三方。第一版不做，匹配不准再升级。
- C. 模型只返回文字，再用一句话解析器：解析器是为口语写的，不适合小票。

配置放哪里：
- **服务器配置文件和环境变量（已选）**。
- 网页设置页：不选，原因见非目标。

## 已定的设计

### 配置

- `data/config.json` 的 `receipt` 对象：`{ url, key, model, format, extra, timeoutSec, dailyLimit }`。
- 环境变量覆盖（优先于配置文件）：`RECEIPT_API_URL`、`RECEIPT_API_KEY`、`RECEIPT_MODEL`、`RECEIPT_FORMAT`（`openai` | `anthropic` | `responses`，默认 `openai`）、`RECEIPT_EXTRA`（JSON 对象，合并进请求体最外层，如 `{"thinking":{"type":"disabled"}}`）、`RECEIPT_TIMEOUT_S`（默认 60）、`RECEIPT_DAILY_LIMIT`（默认 30，0 表示不限）。
- `url`、`key`、`model` 三项齐全才算「已配置」。环境变量和配置文件逐项合并，环境变量优先；`RECEIPT_EXTRA` 整体替换文件里的 `extra`，不做合并。`RECEIPT_EXTRA` 不是合法 JSON 对象时视为未配置，并在服务启动日志里提示（不打印 key）。
- 环境变量的值永远不写回 `config.json`：识别服务的配置通过一个函数在需要时合并文件和环境变量，不要把环境变量塞进会被保存的 `config` 对象。现有 `config.json` 在改密码时会被服务器重写，必须确认重写后文件里原有的 `receipt` 字段不丢。
- `DEPLOY.md` 补充配置说明（推荐用 systemd 的环境变量，key 权限设为仅 root 可读）。

### 请求格式（已用真实小票验证过 openai 与 responses，anthropic 未实测）

三种格式都带一段固定的中文提示词和一张图（`data:<mime>;base64,<数据>`），`extra` 合并进请求体最外层：
- `openai`：`POST url`，头 `authorization: Bearer <key>`；体 `{ model, messages:[{ role:'user', content:[{ type:'text', text }, { type:'image_url', image_url:{ url } }] }] }`；回复文本取 `choices[0].message.content`。
- `anthropic`：头 `x-api-key`、`anthropic-version: 2023-06-01`；体 `{ model, max_tokens: 2000, messages:[{ role:'user', content:[{ type:'image', source:{ type:'base64', media_type, data } }, { type:'text', text }] }] }`；回复文本取 `content` 里所有 `type:'text'` 块的拼接。
- `responses`：头 `authorization: Bearer <key>`；体 `{ model, input:[{ role:'user', content:[{ type:'input_image', image_url }, { type:'input_text', text }] }] }`（`image_url` 是字符串）；回复文本取 `output` 里所有 `type:'message'` 项的 `content` 中 `type:'output_text'` 的拼接。
- 请求超时用 `AbortSignal.timeout`。
- 不设默认的输出 token 上限（各家参数名不同，思考型模型设太小会截断 JSON）；每日次数上限是主要的花费保护。`DEPLOY.md` 里说明可以通过 `extra` 设置 `max_tokens` / `max_completion_tokens` / `max_output_tokens`。读取识别服务的响应时最多读 2 MB，超过按 502 处理。

### 提示词必须包含的规则

只返回 JSON `{"store":"店名","items":[{"name","quantity","unit"}]}`；只列实际购买的商品，不列购物袋、折扣、优惠、小计、合计、运费、包装费；`quantity` 是购买的件数（规格里的重量不算数量），没写就填 1；按重量计价的散称商品，`quantity` 填重量，`unit` 填 kg / 斤 / g；单位从商品名或规格里判断，判断不了填空；商品名保留小票上的写法。具体措辞交给构建者。

### 接口

- `GET /api/receipt/status` → `{ enabled: boolean }`（需登录）。
- `POST /api/receipt/scan`：请求体是图片二进制，`Content-Type` 为 `image/jpeg` | `image/png` | `image/webp`，最大 8 MB；成功返回 `{ text, intents, duplicate, count }`。读取请求体复用现有的 `readImage(req, 8)`（超限时它已返回 413，其他路由的大小限制保持不变）。
  - `text`：确认卡标题，如「小票识别：盒马… 共 8 件」（识别出店名就带上，否则「小票识别：共 8 件」）。
  - `intents`：与 `/api/parse` 返回的意图同形（`action` 为 `add` 或 `restock`，含 `name`、`quantity`、`unit`，新增带 `category`，补货带 `existing`）。
  - `duplicate`：是否疑似重复录入；`count`：识别出的商品数。
  - 识别出 0 件商品时返回 200 和空的 `intents`。
- 错误统一为中文提示，且不回显识别服务的响应原文：400 图片为空、415 类型不支持、413 过大、503「识别服务未配置」、429「今天的识别次数用完了」或「正在识别上一张，请稍等」、504「识别超时」、502「识别服务返回了无法理解的内容，请重拍或手动录入」；识别服务返回 401/403 时回 502「识别服务拒绝了请求，请检查服务器上的 key」。

### 限额、并发与重复

- 每天最多 `dailyLimit` 次，全家共用一个计数，按服务器本地日期计，每次真正转发给识别服务就计一次（含失败）。计数存在 `data/receipt-usage.json`（`{ date, count }`，每次计数后同步写入，跨天自动归零），这样重启或崩溃循环不会让上限失效。
- 同一时间只处理一张图，进行中再来请求返回 429。
- 重复提示：对识别出的商品列表（规范化的名称+数量+单位，排序后）取指纹，内存里保留最近 100 个、48 小时；再次出现相同指纹时 `duplicate` 为 true。仅提示，不拦截。

### 识别结果处理（`lib/receipt.js` 的纯逻辑）

- 从回复文本里取第一个 `{` 到最后一个 `}` 解析，容忍代码块包裹和多余文字。
- 每个商品：`name` 去首尾空白，空的丢弃，最长 60 字；`quantity` 不是大于 0 的有限数则当 1，保留两位小数；`unit` 最长 8 字；最多保留 60 个商品；忽略其他字段和日期。
- **去规格**：从名称中去掉「数字+重量/容量单位」及其附带写法，如 `500g`、`300g/盒`、`250ml*12`、`1.5L`、`2斤`；去完为空则用原名。新增物品用去规格后的名称。
- **匹配库存**：用去规格后的名称，再去掉开头的英文品牌前缀（如 `NB `），交给现有的 `matchItem`（包含匹配）；只对未删除的物品匹配。
- **生成意图**：匹配到 → `restock`；没匹配到 → `add`，分类用现有 `guessCategory`；位置和到期日不设。
- **单位比较**：两个单位「相同」指其中一个为空，或去首尾空白后文字完全相同；不做换算，也不做同义词表（「斤」和「kg」算不同）。
- **补货的单位**：确认卡里补货的单位框预填库存物品的单位，而不是小票的单位（确认卡保存补货时，单位框非空会覆盖库存单位，预填小票单位会悄悄改掉库存单位）。小票单位非空且与库存单位不同时，该条带 `warning`「小票单位「X」和库存单位「Y」不同，请核对数量」。
- **合并**：多行匹配到同一件库存物品，且这些行的单位相互「相同」时，合并成一条补货，数量相加；单位不同的行不合并，改为新增并带 `warning`「和已有「X」单位不同，已作为新物品」。没匹配到的多行若规范化名称相同且单位「相同」，合并成一条新增，数量相加。（原因：确认卡对同一件物品的多条补货都按同一份旧库存快照计算，不合并会丢掉一条。）

### 前端

- 物品页一句话录入表单旁加相机按钮（新增 `i-camera` 图标）；配一个 `accept="image/*"` 的隐藏文件选择框，不加 `capture` 属性，这样既能拍照也能选相册里的截图。
- 登录后请求 `/api/receipt/status`，`enabled` 为 false 就隐藏相机按钮；为 true 时在录入提示文字里加一句「也可以点相机拍小票。图片只发给识别服务，不会保存。」
- 选图后用现有的 `compressImage` 压缩（最长边约 1800px、质量约 0.85，保证小字清楚），上传期间按钮禁用并显示「识别中…」。
- 成功后用现有的确认卡展示：标题用 `text`；`duplicate` 为 true 时顶部加警告「这张小票好像已经录入过了，请确认不是重复。」；提示文字改为「按小票识别，请核对数量和单位；位置和到期日小票上没有，请自己选。」；`intents` 为空时提示「没识别出商品，换张更清晰的图试试」，不弹卡。
- 确认卡写库存的请求不再写死 `?source=quick`，改为按本次来源传入：一句话录入用 `quick`，小票用 `receipt`。变动记录里来源显示「小票」。服务器的 `source` 参数没有白名单，只需在前端的来源名称表（`SOURCE_TEXT`）里加上 `receipt: '小票'`，并更新 `stock_log` 来源的注释。
- 所有错误用 toast 显示服务器返回的中文提示。

## 交给构建者决定

- 相机按钮的具体位置与样式、识别中的提示样式、各处 toast 文案（含义要与上面一致）。

## 我替用户做的决定（请核对）

1. 每天默认 30 次、超时 60 秒、单张图最大 8 MB、重复指纹保留 48 小时 / 100 个，均为我定的默认值，都可配置或可调。每日次数的计数持久化到 `data/receipt-usage.json`，全家共用，避免重启后上限失效。
2. 去规格和合并规则（上面「识别结果处理」一节）是我定的，用户只认可了「匹配库存、有就补货没有就新增」这个大方向。
3. 新增物品的名称保留品牌前缀（如「NB 内酯豆腐」，去掉规格后），用户可在确认卡上改。
4. 识别出店名时放进确认卡标题，仅作显示，不参与其他逻辑。
5. 重复提示的指纹只保存在内存里，重启后丢失。
6. 单位只做「空或文字相同」的比较，不做换算；补货时单位框预填库存单位，单位不同给出警告。
7. 环境变量与配置文件逐项合并（环境变量优先），环境变量永远不写回 `config.json`；`RECEIPT_EXTRA` 非法时按未配置处理。
8. 不设默认的输出 token 上限，靠每日次数上限控制花费；用户可以通过 `extra` 自己加。
